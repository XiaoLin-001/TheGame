## 0. 鐵則：證據或閉嘴

任何「完成／能動／修好了」的聲明**必附證據**：測試輸出、截圖路徑、實跑紀錄。
「應該可以」「理論上沒問題」不是證據。回報時必須引用證據的具體位置（哪個測試、哪張圖、哪行輸出）。

## 0.1 誰判什麼（★ 2026-07-27 定案，全案分工）

| 判官 | 負責 | **明確不負責** |
|---|---|---|
| **agent（Opus 5）** | **程式碼完整性與可讀性**：L1–L3、五支測試、`TL_NAKED` 的視覺編碼檢定、首次體驗的**資訊完備性**（該給的資訊有沒有給、術語會不會勸退、失敗後知不知道原因） | **好不好玩。** agent 不會想再玩一次，也不會困惑——它讀得懂就是讀得懂 |
| **使用者本人** | **樂趣判定**：G1 的樂趣假設、手感、節奏、「還想不想再來一次」 | **首次體驗的真實感受。** 設計者永遠不可能有第一次 |
| **（目前缺席）真人陌生人** | M1 閘門的「無指導 10 分鐘」、真正的可讀性盲測 | — |

**兩條由此而來的硬性規則**：

1. **可讀性驗收一律用 `TL_NAKED=1`。** 拿有數值標籤的截圖問 agent「瓶頸在哪」，它讀數字就答得出來——那是**假綠燈**，驗到的是「我看得懂文字」，不是 R-3 要的「線寬與顏色在傳達資訊」。
2. **凡是判準寫「陌生人」「未受訓玩家」的項目，在拉到真人之前不得標記為通過。** 目前受影響：G2 前的 M1 閘門、§4.4 首次體驗的主觀部分。登記為 **R-14**（`40_PRODUCTION_PLAN.md` §3）。

## 1. 自檢五層梯

**每批工作至少跑 L1–L3；里程碑閘門跑全五層。**

| 層 | 檢什麼 | 本專案怎麼跑 |
|---|---|---|
| **L1 編譯／靜態** | 跑得起來、無腳本錯誤 | `<godot> --headless --path godot --import` 後啟動一次，開機 log 必須乾淨（零 ERROR、零 WARNING） |
| **L2 邏輯測試** | 數值、演算法、存檔遷移、**確定性** | `<godot> --headless --path godot --script res://tests/<name>.gd`，五支全跑＝回歸 |
| **L3 視覺驗證** | 版面、裁切、字型、動效、可讀性 | `TL_SHOT=<png> TL_PANEL=<畫面> TL_SEED=<n>` 產圖，**親眼讀圖**逐項核對。**可讀性項目另加跑一張 `TL_NAKED=1`**（見 §0.1） |
| **L4 冒煙遊玩** | 完整流程：新開局 → 核心循環 → 存檔 → 讀檔 | `TL_SIM=<ticks>` 腳本化跑局；或靜音實玩。**前 60 秒的首次體驗是重點** |
| **L5 找碴審查** | 邊界與惡意 | 見 §4 找碴清單 |

**L3 的常見自欺**：截圖產出來了但沒真的看內容。
**每張驗證截圖都要回答：這張圖證明了什麼？**（元素齊？字沒變豆腐？沒裁切？狀態對？線寬有隨流量變化？）

### 被測試斷言「鎖住」的設計承諾

以下承諾不靠自律，靠測試強制：

| 承諾 | 測試斷言 |
|---|---|
| 科技軸增幅 ≤ +35%（GDD B2 ①） | 科技樹全解鎖後的戰鬥係數上限檢查 |
| 等級軸增幅 ≤ +80%（GDD B2 ②） | 塔與生產節點全滿級後的戰鬥係數上限檢查 |
| **統一配置榜零付費影響**（GDD B3） | 以三組截然不同的存檔（零進度／滿科技／滿等級滿課金）載入每日挑戰的統一配置榜，斷言起始 `SessionState` 完全相同 |
| **雙榜共用同一套邏輯** | 斷言兩榜的地圖、波次表、計分函式為同一份，差異僅在初始化參數 |
| **所有內容純遊玩可取得**（GDD B6） | 斷言每個可購買品項都存在至少一條非付費取得路徑 |
| **無付費復活**（GDD B6） | 斷言失敗流程中不存在任何消費入口 |
| **不賣次數**（紅線 R2） | 斷言不存在限制每日遊玩局數的欄位或閘門 |
| 失敗不扣任何東西（紅線 R1） | 斷言失敗前後的持久狀態雜湊相同 |
| **塔防不依賴 tycoon** | 以「tycoon 從未開啟」的存檔斷言戰役全關卡皆可通過，**且等級軸可推至滿級**（升級材料的塔防路徑必須真的通，GDD §4.1） |
| **能量無全域池**（GDD §3.1） | 斷言拆除所有儲槽後，赤字 tick 的滿足率立即下降——不存在任何隱形緩衝 |
| **儲槽不豁免導管上限** | 斷言 cap 10 的導管上，儲槽單 tick 放電量 ≤ 1.0 單位（10/秒 × 0.1s） |
| **優先權讀類型不讀節點** | 斷言同類型的兩個節點在同一次解算中拿到相同的權重 |
| 有測試鉤子時不寫真存檔 | 斷言 `TL_*` 存在時 `SaveService.persist == false` |
| 招募不重複 | 斷言連抽至畢業，每次結果皆為未擁有角色 |
| 網路不死鎖（GDD §3.1 不變量） | 斷言任意隨機拓樸下，採集器的產出恆 > 0 |

## 4. 找碴清單（L5）

換上 QA 帽，帶著「我要弄壞它」的目標。**每個里程碑閘門必跑一遍。**

### 4.1 數值邊界
- [ ] 資源為 0 時建造、拆除、升級
- [ ] 資源溢位（跑到極大值）時的顯示與運算
- [ ] 導管長度 0（同格連線）、極長導管
- [ ] 優先權全設為同值／全設為最低
- [ ] 塔全部蓋滿導致能量嚴重不足（滿足率趨近 0）
- [ ] 網路完全斷開（孤島節點）
- [ ] 環路：A→B→A、以及多層巢狀環

### 4.2 流程中斷
- [ ] 建造拖曳到一半按 ESC／點空白／切畫面
- [ ] 波次來襲瞬間拆除關鍵節點
- [ ] 提前召喚後立刻再按（連點防護）
- [ ] 準備期快進中被波次打斷
- [ ] 局內直接關遊戲再開（不得留下髒狀態）

- [ ] 存檔檔案損壞／被截斷／非 JSON

- [ ] tycoon：系統時鐘往後調（不得懲罰、不得負數）

### 4.4 首次體驗（前 60 秒，最高優先）

**B0.7 逐條過了一遍**（證據：`b07_first.png`＝空地圖的第一眼，`TL_DEMO_TICKS=0`）。

- [x] 新玩家開局後 15 秒內知道要做什麼嗎？→ **★ B0.7 這一條我打了勾，而使用者拿到 build 的第一句話是「你沒教我要怎麼操作，怎麼玩」。勾是錯的，B0.7.1 補修**：提示列改成**兩行**（上行永遠是下一步、下行是當下動作的細節，預覽不再蓋掉指引），每一句都講出**按哪裡、點哪裡**；新增**「操作說明」抽屜**（空地圖時預設開啟，放下第一個節點後就不再擋路）；路徑上的**來襲方向箭羽**回答「潮從哪來」與「核心在哪」
- [x] 第一次蓋塔時，「它會吃能量」這件事有被明確傳達嗎？→ 放置預覽：`交戰時 −N 能量/秒（待機 0）` ＋ `總能量需求 X → Y /秒（交戰時）`
- [x] 第一次能量不足時，玩家看得出來是什麼原因嗎？→ 能量條的橙色缺口段（脈動）＋ 該塔的 `缺料` 徽章 ＋ 頂欄「交戰 N 座」
- [x] 第一次失敗後，玩家知道自己做錯什麼嗎？→ 局末結算逐項攤開撐過幾波／產能積分／提前召喚加成。⚠ **它講的是「你的產能長什麼樣」，不是「你為什麼被打穿」**——真正的死因歸因（哪一波、哪一段防線破了）未做，登記為 B1.2 戰役框架的項目
- [x] 第一次失敗後，重來按鈕在幾次點擊之內？（必須 ≤ 1）→ **1 次**（結算面板上的「立刻重來」）

> **★ 這五條的判官是我（Opus 5），不是真人。** 能證明的是「該給的資訊有給、給在看得到的地方、而且會隨狀態更新」；**不能**證明「陌生人真的看得懂」——那是 R-14，在拉到真人之前不得標記通過（§0.1）。
>
> **★★ 2026-07-28：這條但書當天就被兌現了，而且方向比預期的更糟。**
>
> 我在 B0.7 把上面五條全打了勾。使用者拿到 build，第一句回饋是**「你沒教我要怎麼操作，怎麼玩」**——連第一條都沒過。
>
> **失效的原因值得記下來，因為它是這一類自檢的通病**：我逐條檢查的是「**資訊在不在**」，而第一條問的其實是「**玩家會不會操作**」。提示列當時寫的是「先在礦點上蓋一台採集器」——資訊確實在，目標也確實明確，**但畫面上從頭到尾沒有任何一個地方說過「蓋」＝左欄選一種、再左鍵點地圖**。對已經知道怎麼玩的人（我）那句話是完整的；對新玩家它少了唯一重要的那一半。
>
> **可稽核的教訓，往後每批照用**：
> 1. **首次體驗的每一句提示都必須包含一個動詞化的操作**（「左欄點 X → 左鍵點 Y」），只講目標不講動作的一律不算過。
> 2. **自檢問「這句話對一個沒讀過程式碼的人夠不夠」，不是問「這個資訊有沒有被顯示」。** 我讀得懂畫面是因為我知道輸入怎麼接的——那正是這條驗收要排除的東西，和 §4.5 用 `TL_NAKED` 遮數字是同一個道理。
> 3. **操作方式本身要有一個常駐可查的地方**，不能只靠情境提示逐步餵——玩家想回頭確認時沒有地方可看。

### 4.5 可讀性（R-3 對策的驗收）
- [x] **★ `TL_NAKED=1` 產出的無數值截圖，Opus 5 能指認出瓶頸節點**（M0 硬性驗收項；答錯＝線寬／顏色沒在傳達，要改視覺編碼，不是換個問法）→ **B0.6 讀圖紀錄見下**
- [x] 導管粗細變化在 1280×720 下肉眼可辨（cap 10 → 28 的四個檔位要看得出差別）
- [x] **能量列（供給/需求）在滿足率下探時的警示足夠醒目**（B0.6 起是一條**圖形**橫條：琥珀＝供給、右段橙色脈動＝短少）
- [x] **儲槽充能列與能量列不會被誤讀成同一件事**（能量是橫條、儲槽是節點上的圓弧，形狀不同）
- [x] 敵潮（品紅）與玩家元素（青／琥珀）在混亂畫面中可瞬間區分
- [x] **跨越點（橋）在地圖上一眼可辨**，玩家不需要試錯才知道哪裡能過
- [ ] `reduce_motion` 開啟後仍能取得全部關鍵資訊 ← **B1.6**（設定畫面在 B1.4 才有）

> **★ B0.6 的 `TL_NAKED` 讀圖紀錄（2026-07-28，判官 Opus 5）**
>
> 圖：`C:/tmp/b06_naked.png`（`TL_NAKED=1 TL_DEMO_TICKS=900 TL_SEED=42`）。畫面上**沒有任何數字**——建造鈕只剩名稱、頂欄整列不畫、提示列不畫。
>
> **問題**：哪個節點塞住了？
> **回答**：右上角那一座（稜鏡 (33,4)）。三個獨立的訊號指同一個地方——① 它上方有一個**橙色倒三角**，全圖唯一；② 它被**琥珀環**圈住＝正在吃電；③ 頂端的**能量條**右段有一截橙色，代表全網供不應求。合起來讀是「電不夠，而付不出錢的是它」。
> **對照**：另外三座塔都沒有倒三角——回收者 (28,6) 有琥珀環（在吃電、吃得飽）、潮鳴 (28,12) 與錨 (32,12) 連環都沒有（待機，耗能 0）。
> **答案核對**：`TL_SIM=900` 的 `badges` 只有 `稜鏡(33,4): 缺料`，`towers.稜鏡.sat = 0.84`。**答對。**
>
> **兩個誠實的但書**：
> 1. **這不是盲測**——編碼是我設計的。這條驗收能證明的是「編碼有承載資訊且彼此不衝突」，不能證明「陌生人也讀得出來」。後者是 R-14，在拉到真人之前不得標記通過（§0.1）。
> 2. **稜鏡自己的幾何體也是三角形**，和 `缺料` 徽章同一個形狀家族。目前靠顏色（合金銀 vs 橙）、朝向（正 vs 倒）、位置（環內 vs 環外上方）三重區分，1× 下仍分得開；但**再有第二座塔用三角形就會出事**，列為 B1.6 美術打磨的追蹤項。

### 4.6 建造合法性與路徑規則（B0.3／B0.4 新增）
- [ ] 在路徑格放節點被擋下，且**說明原因**（不是靜默失敗）
- [ ] 導管跨越非跨越點的路徑格被擋下，且說明原因
- [ ] 導管過跨越點可成功，且**該段全程不受敵人攻擊**
