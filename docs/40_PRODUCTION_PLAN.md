## 1. 里程碑

| 里程碑 | 定義 | 出關標準（閘門） | 狀態 |
|---|---|---|---|
| **M0 原型** | 核心循環可玩，佔位美術，**只做塔防局內** | **G1**：使用者實玩後確認樂趣假設成立——「明知有風險仍選擇再擴一條產線，且破防後想立刻重來」 | ⬜ 未開始 |
| **M1 垂直切片** | 一條完整體驗路徑打磨到最終品質 | 陌生人可無指導遊玩 10 分鐘並理解自己為什麼贏／輸 | ⬜ |
| **M2 Alpha** | 功能完整（內容可缺） | **G2**：`10_GDD.md` §3 系統清單全部實作 | ⬜ |
| **M3 Beta** | 內容完整 | **G3**：`10_GDD.md` §5 內容矩陣填滿 ＋ 零阻斷級 bug ＋ 回歸全過 | ⬜ |
| **M4 Gold** | 出貨 | **G4**：發布檢查表全勾 | ⬜ |
| **營運** | 長線 | `60_LIVEOPS_PLAN.md` 就緒（M3 前產出） | ⬜ |

### 里程碑決策點

- **G1 未過**：不進 M1。優先調整順序為 ①準備期長度 ②塔耗能係數 ③優先權面板的操作成本 ④（若仍不成立）重新檢視「塔吃能量」這條核心機制。
- **M1 結束時複審 tycoon**：若塔防層打磨仍未收斂，製作人有權將 tycoon 降級為「橫向資源的簡化介面」並把完整版移入砍案清單。**此降級需經使用者同意。**
- **M3 前拍板商業模式**（買斷／免費），並據此調整招募系統的呈現。

> 新點子一律先進本節末尾或砍案清單，**不插隊進當前批次**。

## 3. 風險登記簿

| # | 風險 | 影響 | 對策 | 狀態 |
|---|---|---|---|---|
| **R-1** | 純即時不可暫停 × 拉線佈局 → 滑向手速遊戲，違背樂趣核心 | **高**：核心體驗錯位 | 波間準備期（45s／新手 60s）＋藍圖一鍵展開＋建造預覽＋後勤科技降低操作負擔。**M0 第二觀測項** | 🟡 監控中 |
| **R-2** | tycoon 是實質第二個遊戲，範圍與平衡成本翻倍 | **高**：時程 +60~80% | 排在 M2；第一版限縮為單一循環；兩層資源池完全分離；M1 結束時複審是否降級 | 🟡 監控中 |
| **R-3** | 流量網路可讀性不足 → 最佳化樂趣不成立 | **高**：核心機制失效 | 線寬＝流量、顏色＝飽和度、節點三態。**M0 硬性驗收：新玩家 30 秒內指出瓶頸** | 🟡 監控中 |
| **R-4** | 「塔吃能量」造成新手死亡螺旋 | 中 | 新手係數（耗能 ×0.6、準備期 60s、敵人破壞 ×0.7）；能量不足時射速線性下降而非停火 | 🟢 已有對策 |
| **R-5** | 抽卡與買斷制的玩家觀感衝突 | 中 | 抽卡僅遊戲內貨幣、僅橫向內容、不重複有畢業、無賭博語彙。M3 商業模式拍板時複審 | 🟢 已有對策 |
| **R-6** | 三種長線動力（成長／競技／精通）互相稀釋，三頭平行做不深 | 中 | 主軸明確為**成長曲線**；競技（每日挑戰）與精通（難度層）設計為它的自然副產品，共用同一套模擬與分數系統 | 🟢 已有對策 |
| **R-7** | 環路圖的流量解算不收斂或抖動 | 中 | 固定 3 次迭代上限、依 id 排序遍歷保證浮點順序一致；`determinism_test` 每批必跑 | 🟢 已有對策 |
| **R-8** | 大量節點／敵人的渲染效能 | 中 | 模擬 10Hz、渲染 60Hz 插值；導管批繪；敵人不用 Node2D 改資料陣列批繪。每里程碑跑壓力情境 | 🟢 已有對策 |
| **R-9** | 內容量（25 關手作地圖）超出單人產能 | 中 | 地圖以資料表驅動、建立關卡編輯鉤子；若 M3 進度落後，戰役縮至 18 關並補足無盡佈局 | 🟡 監控中 |
| **R-10** | 使用者實玩節奏成為瓶頸（每批都要玩測） | 低—中 | 每批交付前先跑自檢與截圖驗證，把使用者的時間留給「好不好玩」而非「跑不跑得起來」 | 🟢 已有對策 |

## 4. 砍案清單

> 被砍或延後的功能與理由。**留著，避免同一個點子反覆插隊。**

| 功能 | 決定 | 理由 |
|---|---|---|
| 每日簽到獎勵 | 不做 | 使用者未列紅線故技術上開放，但若長線留存需靠簽到撐，代表核心循環失敗。進 backlog 不進排程。 |
| 付費入口（抽卡儲值） | 延後至 M4 商業模式拍板 | 架構已由「橫向供給＋統一榜單」擋住 pay-to-win，但是否開放付費是商業決策 |
| tycoon 的市場價格波動／人事／股價／競爭對手 | 延後 | M2 第一版只做「訂單→產線→交貨→擴廠」單一循環（R-2 對策） |
| 線上排行榜、帳號系統 | 延後至 M4 後 | 第一版純離線；架構已預留（分數與局面可序列化、可重現） |
| 即時 PvP／非同步對戰 | 不做 | 與核心體驗（單人規劃取捨）無關，且需要完整後端 |
| 場上英雄單位（可操作角色） | 不做 | 使用者已明確定義「塔＝角色、全自動開火」；可操作英雄會把重心拉向手感 |
| 迷宮式塔防（玩家可封路改變敵人路徑） | 不做 | 路徑固定是設計選擇——本作的空間策略在「導管怎麼走」，不在「敵人怎麼繞」 |
| 實體物品搬運（Factorio 式輸送帶） | 不做 | 已選定流量網路模型（`30_TECH_DESIGN.md` §2.5），效能、確定性、可讀性、美術四方面皆優 |
| Web／手機版 | 不做 | 交付形式已定為 Windows exe |
| 多語系 | 延後至 M4 | 繁體中文優先；文字集中於資料表，日後抽出成本可控 |
