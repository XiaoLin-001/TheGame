## 4. 砍案清單

> 被砍或延後的功能與理由。**留著，避免同一個點子反覆插隊。**

| 功能 | 決定 | 理由 |
|---|---|---|
| 每日簽到獎勵 | 不做 | 若長線留存需靠簽到撐，代表核心循環失敗。通行證若需每日活躍，以「錯過不懲罰、可補做」的任務形式取代。 |
| 廣告變現（Windows 版） | **不做** | 桌面無可用 SDK 生態、PC 玩家容忍度極低。**保留至手機移植版**，屆時做獎勵式廣告（玩家主動觀看） |
| 付費復活 | **永久不做** | 同時破壞 R1（失敗只花時間 → 變成失敗要花錢）與難度層／排行榜的意義（GDD B6） |
| 體力值／每日局數上限 | **永久不做** | 紅線 R2。F2P 變現改走「賣速度不賣次數」 |
| tycoon 的市場價格波動／人事／股價／競爭對手／員工士氣 | **永久 backlog** | tycoon 已定位為附屬補給站，不是第二個遊戲（`00_CONCEPT.md` §三 約束 4） |
| 線上排行榜、帳號系統 | 延後至 M4 後 | 第一版純離線；架構已預留（分數與局面可序列化、可重現） |
| 即時 PvP／非同步對戰 | 不做 | 與核心體驗（單人規劃取捨）無關，且需要完整後端 |
| 場上英雄單位（可操作角色） | 不做 | 使用者已明確定義「塔＝角色、全自動開火」；可操作英雄會把重心拉向手感 |
| 迷宮式塔防（玩家可封路改變敵人路徑） | 不做 | 路徑固定是設計選擇——本作的空間策略在「導管怎麼走」，不在「敵人怎麼繞」 |
| 實體物品搬運（Factorio 式輸送帶） | 不做 | 已選定流量網路模型（`30_TECH_DESIGN.md` §2.5），效能、確定性、可讀性、美術四方面皆優 |
| Web／手機版 | 不做 | 交付形式已定為 Windows exe |
| 多語系 | 延後至 M4 | 繁體中文優先；文字集中於資料表，日後抽出成本可控 |
