## 1. 願景陳述

> **你的生產線就是你的防線。**

玩家在一張有礦點與敵人路徑的地圖上，用**節點**與**導管**蓋出一套會自己運轉的生產網路；同一套網路同時餵養**塔（角色）**。塔不是蓋完就免費站著——**它持續消耗你的能量產出**。於是「防線再厚一點」與「產能再大一點」是同一條資源曲線的兩端，每一秒都在互相扣減。

**樂趣假設（G1 唯一驗收標準）**：
> 玩家會在波次倒數剩 40 秒時，明知有風險仍選擇再擴一條產線——並且在防線破掉之後想立刻重來一次。

**憲法級平衡哲學**（前期定死，生產期不重談）：

| # | 決策 | 內容 |
|---|---|---|
| B1 | 成長用**加法為主、乘法為輔** | 科技樹以「+2 吞吐」「+15% 效率」為主，禁止出現 ×2 以上的乘算堆疊，避免後期數值爆炸與平衡失控。 |
| B2 | **局外成長分兩軸，各有不同天花板** | **① 科技軸**（研究數據，只能靠遊玩取得）：全解鎖對戰鬥數值總增幅 ≤ **+35%**。<br>**② 等級軸**（tycoon 升級材料，可掛機／可加速取得）：塔與生產節點各 10 級，每級 +8%，滿級 **+80%**。<br>**硬性配套：等級軸的增幅必須被難度層同步吃掉**——難度層 N 的敵人強度縮放係數以「等級軸滿級」為基準校準。**等級軸買到的是「能挑戰更高難度層」，不是「碾壓現有內容」。**<br>局內只有臨時升級（隨局結束消失）。 |
| B3 | **競技分層：一榜純技術，一榜比戰力** | 每日挑戰跑**雙榜**，同種子、同地圖，只有起始配置不同：<br>**① 統一配置榜**——固定角色組、固定科技、固定等級；不論進度、抽卡或課金，所有玩家起始能力完全相同。<br>**② 自由配置榜**——玩家的完整戰力。<br>**統一配置榜永遠存在、永遠免費、永遠可爭第一。不得移除、不得收費、不得加入任何付費影響因子。**<br>**誠實註記**：第一版純離線（§3.10），兩榜實際上是本機最佳成績，沒有對手。**「對 P2W 的制衡」是接上線上榜之後才兌現的承諾**——在那之前它是架構保留，不是既成事實。不要在文案或對外說明中宣稱一個尚未存在的競技場。 |
| B6 | **賣速度，不賣次數，不賣進度** | F2P 變現只能**加快**既有路徑。所有內容與進度都必須能純靠遊玩取得（付費只是省時間）。<br>禁止：賣遊玩次數／體力（紅線 R2）、賣重試權、賣關卡解鎖鑰匙、**付費復活**（同時破壞 R1 與難度層／排行榜的意義）。 |
| B4 | **失敗只花時間** | 對應紅線 R1。任何失敗不扣除任何已獲得物。 |
| B5 | **不可暫停，但可跳過等待** | 戰鬥中固定 1× 速度。**準備期**可快進（跳過空等），戰鬥階段不可加速也不可減速。 |

## 2. 核心循環

### 2.1 局內循環（一圈 60–120 秒）

```
        ┌──────────────────────────────────────────────────┐
        │                                                  │
        ▼                                                  │
  ①勘查 ──► ②拉線佈產 ──► ③資源流動 ──► ④【取捨】───┐      │
  讀地形     動詞：放節點    回饋：線變粗   擴產 or 築防  │      │
  找礦點     ＋連導管        數字上升                    │      │
  找路徑                                                 │      │
                                                         ▼      │
                              ⑦準備期修補 ◄── ⑥缺口暴露 ◄── ⑤波次來襲
                              45 秒可規劃      學習：哪條線      壓力：塔開火
                              可快進           不該那樣走        持續吃能量
                                     │                                 │
                                     └─────────────────────────────────┘
```

**每一步的時長與爽點**：

| 步驟 | 時長 | 爽點 |
|---|---|---|
| ① 勘查 | 15 秒（首波前） | 「這張圖的礦點分佈很刁鑽」的解謎感 |
| ② 拉線佈產 | 20–40 秒 | 線亮起、資源開始流動的即時回饋 |
| ③ 資源流動 | 持續 | **線的粗細會隨實際流量變化**——看得見自己的網路在呼吸 |
| ④ 取捨 | 5–10 秒的決定 | **本作的心臟**。多一座塔＝少 8 能量/秒＝熔爐慢 20% |
| ⑤ 波次 | 20–40 秒 | 塔自動開火、能量條下探、線被打斷的緊張 |
| ⑥ 缺口暴露 | 即時 | 「早知道那條線該繞後面」的懊悔＝學習 |
| ⑦ 準備期 | 45 秒（可快進） | 修補、擴張、下注（提前召喚） |

### 2.2 外層循環（跨局）

```
打完一局 ──► 結算：研究數據＋稀有原料＋聲望
                │
                ├──► 科技樹（產能／防務／後勤三支）──► 下局起手更強、選擇更多
                ├──► 名冊（解鎖／抽卡新角色）────────► 下局玩法組合改變
                └──► 潮汐公司（tycoon，M2）─────────► 升級材料、招募券、藍圖槽、難度鑰匙
                                │
                                └──► 回到「再打一局」
```

### 2.3 長線留存的三根支柱

tycoon 已定位為**附屬補給站**而非獨立遊戲（§3.8），因此**留存不能靠「換個遊戲玩」**。三根支柱各自承擔不同的回訪動機：

| 支柱 | 回訪動機 | 節奏 |
|---|---|---|
| **成長曲線** | 「我的科技樹再推兩格就能解鎖那隻塔」 | 每次遊玩都在推進 |
| **每日種子挑戰** | 「今天的圖跟昨天不一樣，我想試試」 | 每天一次的新鮮理由 |
| **難度層精通** | 「上一層我差三波就過了」 | 卡關時的長期目標 |

**tycoon 的留存角色是「低壓力的短暫停留」**：打完一局進去收成、排下一批訂單、看著數字長，一兩分鐘就走。它降低關遊戲的動作成本，但它**不是**疲勞出口——真正的疲勞出口是**換一種塔防玩法**（戰役 ↔ 無盡 ↔ 每日挑戰，三種節奏完全不同）。

## 3. 系統清單

> **紀律**：每個系統都必須回答「服務核心循環的哪一步」。答不出來的進 backlog，不進 GDD。

### 3.1 流量網路（Flow Network）★核心
**服務循環步驟**：②③④　|　**里程碑**：M0

本作的自動化不是物件模擬（不搬運實體物品），而是**流量網路解算**。這是同時滿足效能、確定性、可讀性、極簡美術的唯一選擇。

**物件模型**：

| 概念 | 定義 |
|---|---|
| **節點 Node** | 地圖上的建築。有座標、生命值、輸入埠需求（demand）、輸出埠供給（supply）、內部處理速率。 |
| **導管 Line** | 連接兩節點的有向邊。有長度、吞吐上限（cap）、生命值、當前流量（flow）。 |
| **網路 Network** | 節點與導管構成的有向圖。每 tick 解算一次分配。 |

**解算規則**（純函式、零 RNG、確定性）：

1. 每 tick（0.1 秒）為一個解算週期。
2. 依資源種類分別解算（礦砂網、能量網、合金網互不干擾）。
3. 每個消費節點聲明 `demand`，每個生產節點聲明 `supply`。
4. 沿圖做**容量受限的比例分配**：若某導管的請求總量 > `cap`，所有下游按**優先權加權**後等比例削減。
5. 消費節點拿到的量 < demand 時，以 `滿足率 = 實得/需求` 線性降低其產出或效能（**不直接停機**——避免全網崩潰的雪崩感）。
6. 解算完成後寫回每條導管的 `flow`，供視覺化使用。

**供不應求時的行為（重要設計決策）**：

當 `demand > supply` 時，本作**不停機，改為按比例降速**：`實際效能 = 標稱效能 × 滿足率`。

| 為什麼不停機 | 說明 |
|---|---|
| **停機會雪崩** | 能量不足 → 塔停火 → 敵人活更久 → 打壞更多導管 → 能量更少 → 全滅。玩家無法指出自己在哪一步輸的。降速是漸進的，玩家在 60% 效能下仍有搶救空間 |
| **降速可診斷** | 節點直接顯示「60% 飢餓」，玩家一眼知道缺口多大。停機只傳達「壞了」，不傳達「差多少」 |
| **與紅線一致** | R1「失敗只花時間」隱含「玩家要能看懂自己為什麼輸」。雪崩式崩潰違反這一點 |

> **真實工廠確實是批次運作**（湊不滿一批就停機）。本作刻意不模擬這一點——那是寫實感的代價，而我們要的是可讀性與可救性。

**★ 能量是流率，不是水池**（2026-07-27 定案）：

**沒有全域能量池。** 每 tick 的供給與需求就地結算，能量不會自動累積在某個看不見的帳戶裡。**唯一的儲存體是儲槽節點，它有座標、有導管、有射程外的距離。**

| | 決策 |
|---|---|
| 頂欄顯示 | `能量 40/63 ⚠`＝**本 tick 供給／需求**（滿足率 63%）。不是存量／容量。 |
| 儲槽顯示 | 另列 `儲槽 340/600`＝全部儲槽的充能總和／總容量。 |
| 儲槽解算語意 | 全網盈餘時它是**消費者**（充能，吃優先權權重）；赤字時它是**供給者**（放電）。充放電速率**受它自己那條導管的 `cap` 約束**——這是它與全域水池的根本差別。 |

**為什麼不做全域水池**：水池不需要管線送電，於是儲槽變成「+300 容量」的被動配件，蓋在地圖哪個角落都一樣。那會同時廢掉三件事——儲槽的「核心策略建築」定位、導管加粗的取捨（§7.2）、以及「你的生產線就是你的防線」這個空間論述。**儲槽放遠了、幹線沒加粗，它的電就趕不到稜鏡那裡**，這正是我們要的。

**★ 不變量：網路永不全域死鎖。**
**採集器沒有任何輸入需求**（只要蓋在礦點上就出礦）。因此網路永遠存在一個不依賴任何其他節點的源頭，結構上不可能出現「A 等 B、B 等 A」的全域凍結。
**任何新增的生產節點都不得破壞此不變量**——若未來要加入「需要能量才能採礦」的節點，必須同時保留至少一種零輸入的採集手段。

**優先權面板（本作最重要的 UI 元件）**：
玩家為**每一種節點類型**（錨／稜鏡／潮鳴／回收者／熔爐／儲槽／…）設定 1–5 的優先權。**當能量不足時，優先權決定誰先餓死：塔停火，還是熔爐停產。** 這把「痛苦的取捨」做成一個玩家隨時可以拉的滑桿——它不是選單設定，它是戰術動作。

**★ 為什麼是「依類型」而不是「依節點」**（2026-07-27 定案）：

1. **戰術動作必須是一個手勢。** 遊戲不可暫停。滑桿永遠在同一個位置＝一個手勢；在地圖上找到那顆節點再拖它＝兩三個手勢。依節點會把最重要的戰術動作變成操作負擔（R-1）。
2. **操作負擔必須恆定。** 依節點的話，蓋 20 座塔就有 20 條滑桿要管——每蓋一座建築就多一個要顧的東西，這是操作負擔的滑坡。依類型永遠是 5–8 條。
3. **依節點解的是耗能模型已經解掉的問題。** 待機耗能為 0，沒開火的塔本來就不吃電；「這座稜鏡比那座重要」只在兩座都在交戰時才存在，而兩座都在交戰就代表兩座都有敵人要打。單體差異已由每座塔各自的**目標選擇**（§3.3）承擔。
4. 面板恆為 5–8 條，44×44 px 觸控命中區放得下（`20_ART_DIRECTION.md` §1.3b P2）。

**儲槽在優先權面板佔一格**：盈餘時它是可調的低優先權消費者（充能搶不搶得贏熔爐），赤字時它是供給者。這讓「這一波要不要留電」成為一個戰術決定。

**可讀性規範**（風險 3 的對策，硬性要求）：
- 導管**粗細 = 實際流量 / 吞吐上限**
- 導管**顏色**：正常（青）／飽和（亮青，滿載）／飢餓（暗青閃爍）
- 節點三態徽章：`缺料` / `滿溢` / `正常`
- **驗收標準（★ 執行方式已定案）**：以 **`TL_NAKED=1`** 產出**隱藏全部數值標籤**的截圖——只留線寬、顏色、三態徽章——交 Opus 5 指認瓶頸節點，答對才算過。
  *為什麼不是「找個未受訓玩家」*：本案沒有這個人（樂趣與首次體驗由使用者本人判，而他是設計者；agent 只驗程式碼與可讀性）。而拿**有數字**的截圖問 agent 一定會過——它答對的是「我讀得懂 `能量 40/63`」，不是「線寬與顏色在傳達資訊」。遮掉數字才驗得到真東西。詳見 `30_TECH_DESIGN.md` §4.1、`50_QA_PLAN.md` §0.1。

### 3.2 建造系統
**服務循環步驟**：②⑦　|　**里程碑**：M0

- **放置**：從建造面板選節點類型 → 地圖上點擊放置。網格對齊（32px）。
- **連線**：點起始節點 → 拖到目標節點 → 生成導管。可經中繼節點轉折。
- **成本**：節點有固定造價；導管造價 = `長度(格) × 單位成本`。
- **即時預覽**：拖曳中顯示「這條線會帶來 +X/秒」與「總耗能將變為 Y/秒」。**這是把取捨資訊在決策前就攤開給玩家看**，不讓玩家事後才發現餓死了。
- **拆除**：返還 50% 成本。
- **禁止事項**：不可在敵人路徑格上建造**節點**（路徑是既定的，玩家不能封路——這不是迷宮塔防）。

#### ★ 跨越點（橋）— 路徑上唯一可鋪管的地方

地圖作者在敵人路徑上指定若干**跨越點**。規則：

| 項目 | 規則 |
|---|---|
| 可鋪 | **導管**可以鋪過跨越點 |
| 不可鋪 | **節點**（含中繼）一律不可——它們會擋路 |
| 安全性 | **橋是架高的 → 橋上的導管不受敵人攻擊**（§3.5） |
| 數量 | 由地圖作者決定，是**關卡設計的主要刻度尺**——一座橋的圖跟四座橋的圖是兩款遊戲 |

**設計意圖**：路徑把地圖切開，跨越點決定你的網路能怎麼縫回去。橋是安全動線，所以「該不該為了短路而貼著路徑走」這個取捨仍然存在（貼路的線會被打，§3.5），但玩家永遠有一條可規劃、不會被打斷的幹線選擇。這同時避免了「唯一通路被打斷 → 整側斷電」的雪崩，與 §3.1 的反雪崩原則一致。

**視覺**：跨越點在地圖上明示（見 `20_ART_DIRECTION.md` §1.6），玩家不需要試錯才知道哪裡能過。

### 3.3 塔（角色）系統 ★
**服務循環步驟**：④⑤　|　**里程碑**：M0

**塔即角色**：每個角色是一種可放置的防禦建築，**全自動開火**，射程內即攻擊，玩家不下達戰鬥指令。

**通用屬性**：

| 屬性 | 說明 |
|---|---|
| 造價 | 礦砂／合金 |
| **交戰耗能** | **射程內有目標時，每秒持續消耗能量**（與射速無關） |
| **待機耗能** | **預設 0**——射程內無敵人時幾乎不耗電。少數提供持續全域效果的特殊角色例外（未來設計時逐一標註） |
| 射程／射程形狀 | 圓形／扇形／直線 |
| 傷害類型 | 物理（被護甲減免）／能量（被屏障減免） |
| 目標選擇 | 最近／最前／最高血量／最低血量（玩家可設） |
| 特殊機制 | 每個角色獨有 |

#### ★ 耗能模型：峰值約束，不是平均約束

塔**只在交戰時耗電**。這把核心取捨從「持續扣血」變成**尖峰衝擊**：

```
準備期（45 秒）        波次期（20–40 秒）
塔耗能 ≈ 0             全部塔同時開火 → 耗能暴增
生產線滿速運轉          生產線被塔搶電 → 產能驟降
儲槽充能 ↑↑            儲槽放電 ↓↓
```

**這條規則的三個後果**（全部是設計意圖，不是副作用）：

1. **儲槽 Silo 從「緩衝配件」升格為核心策略建築。** 你在準備期充能、波次期放電。儲槽容量直接決定你能養幾座塔。
2. **約束變成「峰值電力」而非「平均電力」。** 多蓋一座塔的代價不是持續的漏電，而是**波次期的電力缺口更大** → 你必須擴發電或擴儲槽 → 那些資源就不能拿去擴礦。取捨完好無損，只是換了發生的時刻，而且更戲劇性。
3. **提前召喚變得更兇。** 提前開波 = 提前讓工廠停擺、提前開始燒儲備電。下注的張力提高。

**能量不足時的行為**：射速按滿足率**線性下降**（滿足率 60% → 射速 60%），不會完全停火（理由見 §3.1 供不應求）。潮鳴的光環強度同樣按滿足率縮放。

#### ★ 全域規則：擊殺回收

**任何塔擊殺敵人，都回收該敵人價值 25% 的礦砂。** 這是全域規則，不是特定角色的能力。

設計意圖：讓防禦本身帶有經濟回饋，緩和「多蓋塔 = 純虧」的直覺，並讓高擊殺效率的佈局自然獲得經濟優勢。

#### ★ 礦砂↔能量匯率：**1 礦砂 = 5 能量**

敵人的「價值」（§7.5）以**礦砂**計。任何把價值換算成能量的地方一律用這個匯率，它不是新發明的數字——它就是發電機的轉換比（§7.3：4 礦砂/秒 → 20 能量/秒）。目前唯一的用處是回收者的能量回收。

**M0 四隻角色**（覆蓋四種戰術定位，足以驗證核心取捨）：

| 角色 | 定位 | 傷害型 | 特色 | 設計意圖 |
|---|---|---|---|---|
| **錨 Anchor** | 基礎 | 物理 | 短射程、高單體傷害、**交戰耗能低** | 便宜可靠的地基。教會玩家「開火才要錢」的成本概念。 |
| **稜鏡 Prism** | 爆發 | 能量 | 直線穿透雷射，可同時打穿一整列敵人、**交戰耗能極高** | 取捨的極端案例：一座稜鏡開火時 ≈ 五座錨。它讓儲槽容量成為硬需求。 |
| **潮鳴 Knell** | 控場 | 無傷害 | 範圍減速 −40%、破甲 −25%，交戰耗能中 | 證明「不造成傷害的建築也值得佔用電力」。光環僅在射程內有敵人時啟動（＝交戰狀態）。 |
| **回收者 Reclaimer** | 經濟 | 物理 | 中等傷害，**射程內任何敵人死亡（不限自己擊殺）即回收其價值 60% 為「能量」注入電網**（匯率 1 礦砂 = 5 能量，見上） | **打破峰值約束的鑰匙**：唯一能在波次進行中補充電力的塔。因為算的是「射程內的死亡」而非「自己的擊殺」，它的擺放是一道空間謎題——要放在殺戮最密集處，而不是它自己射得最爽的地方。長波次與無盡模式的核心建築。 |

> **回收者的定位為何改變**：既然「擊殺回收礦砂」已成為全域規則（見上），原本的「回收礦砂 30%」失去獨特性。改為**回收能量**後，它直接對抗新耗能模型製造的峰值缺口——這使它成為長波次的關鍵解答，且與礦砂經濟不重疊。

**擴充角色**（M2 起，見 §5 內容矩陣）：目標 24 隻，其中 6 隻為抽卡專屬稀有角色。

### 3.4 波次與壓力系統
**服務循環步驟**：⑤⑦　|　**里程碑**：M0

- **波次表**：每關預先定義的敵人組成序列（戰役手作，無盡程序生成）。**確定性**：同種子必同波次。
- **準備期**：波與波之間 45 秒安全窗口（戰役第 1–5 關為 60 秒）。**時間與生產持續流動**，只是沒有敵人。可快進。
- **提前召喚**：準備期內任意時刻可按下，立即開波。
  - 獎勵倍率 = `1 + (剩餘秒數 / 準備期總長) × 0.5`（最高 +50%）
  - 獎勵形式：該波掉落的礦砂與研究數據按倍率增加
  - **設計意圖**：把取捨從「被動承受」變成「主動下注」。這是分數天花板的主要來源，也是高手與新手的分野。

### 3.5 敵人系統
**服務循環步驟**：⑤⑥　|　**里程碑**：M0

- **行為（★ walk-by，2026-07-27 定案）**：敵人沿預定路徑推進，**永不停步**。每 tick 對**相鄰 1 格內**的玩家建築造成其「對建築傷害」，然後繼續走。**只有核心會讓它們駐足**（停下來打到核心歸零）。
- **例外**：**跨越點（橋）上的導管不受攻擊**——橋是架高的（§3.2）。
- **為什麼不做「停下來攻擊」**：一旦敵人會為建築駐足，玩家就會發現丟一排 15 礦砂的中繼是最便宜的拖時間道具——那等於把**迷宮塔防**偷裝回來（它在砍案清單上），而且波次長度變得不可預測，提前召喚的下注也算不清。walk-by 沒有索敵邏輯、沒有停頓、波次長度恆定。
- **關鍵設計**：**敵人會打斷你的線。** 這讓佈局有了空間策略——貼路徑走的線短、便宜、危險；退開一格就安全但長、貴；橋是唯一又短又安全的路，而橋有幾座是地圖作者決定的。沒有這一條，塔防就只是「保護一個點」。
- **塔的擺位**：塔的射程 4–9 格遠大於 1 格的破壞半徑，所以塔可以站在安全距離外開火。**願意把塔（或線）壓到路邊，換的是覆蓋率與長度，賭的是它撐不撐得住。**
- **屬性**：

| 屬性 | 效果 | 剋制方式 |
|---|---|---|
| 護甲 Armor | 物理傷害 −N | 能量傷害、潮鳴破甲 |
| 屏障 Barrier | 能量傷害 −N% | 物理傷害 |
| 迅捷 Swift | 免疫減速 | 高爆發單體 |

- **失敗條件**：核心生命歸零 → 本關失敗 → 可立即重來（**無任何損失**，紅線 R1）。

### 3.6 科技樹
**服務循環步驟**：外層　|　**里程碑**：M1

三支路線，用**研究數據**解鎖：

| 路線 | 內容 | 上限 |
|---|---|---|
| **產能** | 導管吞吐、採集速度、熔爐效率、儲槽容量 | 合計 +35%（B2） |
| **防務** | 塔傷害、射程、**交戰耗能效率**（最重要的一項） | 合計 +35%（B2） |
| **後勤** | 藍圖槽數量、優先權精度、建造返還率、預覽資訊深度 | 無數值上限（純便利性） |

**設計意圖**：後勤支不給數值，只給**操作品質**——這是對「不可暫停可能變手速」風險的長線解藥：玩得越久，操作負擔越低，思考空間越大。

### 3.7 藍圖庫
**服務循環步驟**：②⑦　|　**里程碑**：M2

- 框選一組節點與導管 → 存為藍圖。
- 下局在建造面板一鍵展開（自動計算成本，資源不足則顯示缺口）。
- 藍圖槽數量由後勤科技與 tycoon 供給。
- **設計意圖**：消除「每局前 10 分鐘重複勞動」，同時把玩家的精通結晶化——你的藍圖庫就是你的技術資產。

### 3.8 潮汐公司（tycoon）— 塔防的後勤補給站
**服務循環步驟**：外層供給　|　**里程碑**：M2

> **定位（2026-07-27 修訂）**：tycoon **不是**可獨立遊玩的第二個遊戲，而是塔防的**附屬資源供應系統**。
> 它的存在理由只有一個：**穩定供給塔防所需的資源與升級材料**。任何「讓 tycoon 本身變得好玩到可以取代塔防」的提案一律進 backlog。

**核心循環**（刻意保持單薄）：
```
接訂單（品項、數量、交期、報酬）
  → 排產線（複用流量網路引擎，無敵人、無時間壓力）
  → 生產累積（在線即時／離線掛機）
  → 交貨結算 → 資金與材料
  → 擴廠（產線位）／研發（新品項）
  → 接更大的訂單
```

**產出（全部流向塔防）**：

| 產出 | 用途 |
|---|---|
| 資金 Credit | 兌換以下各項 |
| 升級材料 | 塔的等級、生產節點的等級（**數值強化**） |
| 招募券 | 名冊招募 |
| 藍圖槽、難度鑰匙、外觀 | 橫向內容 |

**掛機規則**：離線時持續生產，受**倉儲上限**約束（滿了停產）。倉儲上限可升級。
**這不是體力閘門**（紅線 R2）：它不限制你能玩幾局塔防，它是「回來收成」的正向設計。塔防隨時可以玩，不需要任何 tycoon 產物。

**塔防 → tycoon 的回流**：塔防局掉落的稀有原料可加速高階訂單。tycoon 也能自行採購（較貴），因此**掛機路線與遊玩路線都走得通**。

**設計約束（防止它膨脹成第二個遊戲）**：
1. tycoon **沒有失敗狀態**、沒有時間壓力、沒有對手。它是水龍頭，不是挑戰。
2. tycoon 的 UI 深度上限：**兩個畫面**（訂單板＋產線編輯）。超過就是膨脹。
3. tycoon 的任何新機制都必須回答「這如何讓塔防更好玩」。答不出來就不做。
4. 市場價格波動、人事系統、股價、競爭對手、員工士氣 → **永久 backlog**。

**M2 第一版範圍**：只做「訂單 → 產線 → 交貨 → 擴廠」單一循環。

### 3.9 名冊與招募
**服務循環步驟**：外層　|　**里程碑**：M2

- **確定性解鎖**（主要途徑，18 隻）：科技樹、戰役關卡獎勵、成就、商店直購。玩家能規劃「我再推兩關就能拿到那隻」。
- **招募（抽卡）**（6 隻稀有角色）：用聲望券抽「潮汐名冊」。
  - **不重複**：抽到的必定是尚未擁有的稀有角色。隨機的是**順序**，不是有沒有。
  - **有畢業**：UI 常駐顯示「還剩 N 隻未收集」。抽完即畢業，不再消耗券。
  - **不使用賭博語彙**：無十連演出、無稀有度金光、無「差一點就中」的假張力。
  - **不影響統一配置榜**：該榜使用固定角色組，抽卡結果完全不進入（B3）。自由配置榜才會反映。
- **聲望券來源**：戰役里程碑、成就、tycoon 產出、無盡分數門檻，**以及付費購買**。
- **B6 保障**：6 隻稀有角色**全部都能純靠遊玩取得**（券的產出速率保證在合理時間內可畢業），付費只是加快。不存在「只能課金拿到」的角色。

### 3.10 排行榜與每日挑戰
**服務循環步驟**：長線引擎　|　**里程碑**：M2

- **每日挑戰**：全球同一固定種子（`seed = hash(日期)`）。**同一張圖跑兩榜**：

| 榜 | 起始配置 | 目的 |
|---|---|---|
| **統一配置榜** | 固定角色組、固定科技、固定等級、固定起始資源。**與玩家的任何進度與課金完全無關** | 純技術競爭。免費玩家爭第一的舞台。**對 P2W 的唯一制衡（B3）** |
| **自由配置榜** | 玩家的完整戰力（自選角色、自己的科技與等級） | 成長曲線的展示場；付費的兌現點 |

- **實作成本極低**：兩榜共用同一套地圖、波次、模擬與計分，差異只在 `SessionState` 的初始化參數。**不得為此拆成兩套邏輯。**
- **第一版純離線**：本機保存每日兩榜的最佳成績與歷史紀錄。**誠實註記**：離線狀態下兩榜是兩個本機數字，沒有排名、沒有對手。雙榜架構此時的價值是**接線上榜時零改動**，不是「已經在制衡 P2W」（B3）。
- **架構要求**：分數、局面、操作序列全程可序列化、可重現（見 `30_TECH_DESIGN.md` §2 確定性）。日後接線上榜**不需重寫核心**。
- **無盡模式**：程序生成地圖 + 無限波次，個人最佳紀錄（自由配置）。

### 3.11 難度層
**服務循環步驟**：長線引擎（深度精通）　|　**里程碑**：M3

通關戰役後解鎖，逐層疊加更嚴苛的規則（例：塔交戰耗能 +20%、敵人破壞導管速度加倍、準備期縮短為 30 秒）。共 12 層。成本極低（純數值與規則開關），是深度精通的主要載體。

**★ 難度層同時是等級軸的配重**（B2 ②）：每層的敵人強度縮放係數**以「等級軸滿級」為基準校準**，因此買到滿級不會碾壓既有內容，而是讓你有資格挑戰下一層。這是本作處理 P2W 數值膨脹的主要機制（`00_CONCEPT.md` 風險 6）。

### 3.12 變現系統
**服務循環步驟**：外層（不進入核心循環）　|　**里程碑**：M4

**免費遊玩 ＋ 內購。Windows 版無廣告。**

| 商品 | 內容 | 性質 |
|---|---|---|
| tycoon 加速／立即收成 | 跳過生產等待、立即結算離線收益 | 賣時間 |
| 升級材料包 | 等級軸材料（B2 ②） | **P2W 成分**，由難度層縮放配重 |
| 聲望券 | 招募稀有角色 | 賣時間（全角色皆可遊玩取得） |

**硬性約束（B6）**：
- ❌ 不賣遊玩次數／體力（紅線 R2）
- ❌ 不賣重試權、關卡解鎖鑰匙
- ❌ **不做付費復活**
- ❌ 統一配置榜不得受任何付費項目影響（B3）

**廣告**：Windows 版不做。手機移植版（若成案）以獎勵式廣告為主：玩家**主動**觀看換取 tycoon 加速或材料。不做插播、不做強制觀看。

**★ 升級材料必須有三條路（2026-07-27 修正）**：原本只寫「tycoon 交貨」一條，那會讓不碰 tycoon 的玩家雖然推得完戰役、卻永遠拿不到等級軸，於是上不了高難度層——直接違反 `00_CONCEPT.md` §三「塔防不依賴 tycoon」與 B6「所有進度都必須能純靠遊玩取得」。**塔防局末結算必須是升級材料的一條完整路徑**（速率可以慢於 tycoon，但不得為零）。B2.7 以測試斷言鎖住：以「從未開啟 tycoon」的存檔可將等級軸推至滿級。

**防通膨機制**：
- 局內資源（礦砂／能量／合金）**每局歸零**，不跨局累積 → 結構上不可能通膨。
- 研究數據：科技樹總量有限（B2 上限 +35%），走滿即封頂。
- 資金：tycoon 的擴廠成本呈**指數上升**（×1.35/級），配合線性收入增長，形成自然的收斂曲線。
- 聲望券：抽卡池僅 6 隻且不重複，抽完畢業 → 券的需求有明確終點。

### 4.2 成長曲線公式

| 對象 | 公式 | 說明 |
|---|---|---|
| 科技樹節點成本 | `cost(n) = 50 × n^1.6` | n = 該支已解鎖數。前期便宜、後期需要多局累積。 |
| tycoon 擴廠成本 | `cost(L) = 500 × 1.35^L` | L = 當前廠等。 |
| tycoon 訂單報酬 | `reward(L) = 120 × L^1.25` | 線性偏下，配合指數成本形成收斂。 |
| 無盡波次強度 | `hp(w) = 100 × 1.11^w`，`count(w) = 4 + floor(w/3)` | 指數血量 + 線性數量。玩家產能需同步指數成長才撐得住 → 天然的技術檢定。 |
| 局末研究數據 | `data = 10 × 波次數 + 2 × 產能積分 + 提前召喚加成` | 產能積分 = 全局平均每秒總產出 / 10 |

### 4.3 局內臨時升級

局內可用礦砂即時升級單座建築（+1 級，最多 3 級），**隨局結束消失**（B2）。這給予局內的短期成長回饋，同時不污染跨局平衡。

**HUD 設計硬性要求**：
1. **能量列是全畫面最醒目的元件**——它是取捨的化身。顯示的是**本 tick 供給／需求**（滿足率），不是存量／容量（§3.1）；滿足率下探時整列變色並脈動。
2. **建造預覽必須在決策前顯示總耗能變化**，不讓玩家事後才發現餓死。
3. **提前召喚按鈕常駐顯示當前獎勵倍率**，讓下注的誘惑一直在眼前。
4. 準備期與戰鬥期的**畫面色調不同**（準備期偏冷靜的青、戰鬥期加入警示暖色），讓玩家不必看計時器也知道自己在哪個階段。
5. **浮層不得遮住路徑與跨越點**。面板可收合；收合狀態下地圖 100% 可見。
6. **所有面板項目的觸控命中區 ≥ 44×44 px**（`20_ART_DIRECTION.md` §1.3b P2）。這是把面板改成浮層／抽屜的直接原因之一——固定窄欄塞不下 9 個 44px 的建造項目。

**全域擊殺回收**：任何塔擊殺敵人 → 回收該敵人價值 **25%** 的礦砂。回收者的能量回收與此**並存**（同一次擊殺可同時產生礦砂與能量）。

**★ 回收者的能量回收算式**：`能量 = 敵人價值(礦砂) × 60% × 5`（匯率見 §3.3）

| 敵人 | 價值 | 回收能量 |
|---|---|---|
| 漂蟲 | 12 礦砂 | **36** |
| 熾泳 | 22 礦砂 | **66** |
| 甲殼 | 30 礦砂 | **90** |

*校準基準*：回收者一波耗 7 × 30s ＝ 210 能量。射程內死 10 隻（均價 20 礦砂）＝ 回收 600 能量，淨 +390 ≈ 0.65 台發電機——不吃礦砂燃料，但要靠擊殺密度。**條件式強勢，形狀健康**。若實測回收者變成必蓋或廢物，先動的是 60% 這個數字，不是匯率。

**能量不足時**：`實際射速 = 基礎射速 × 滿足率`，滿足率 = 實得能量/需求能量。潮鳴的光環強度同樣按滿足率縮放。

**峰值電力參考算式**（設計數值時的校準基準）：

> **前提：本表假設幹線導管已升到足夠 cap**（§7.2）。基礎 cap 10 送不出 20/秒的發電機輸出，也放不出 23/秒的儲槽缺口——**加粗幹線的礦砂成本要算進下表的每一列**。

| 情境 | 波次期峰值耗能 | 發電配置 | 缺口 | 儲槽支撐時間 | 幹線需求 |
|---|---|---|---|---|---|
| 早期：4 錨 | 16 /秒 | 1 發電機（20） | 盈餘 +4 | — | cap 16（升 1 級） |
| 中期：6 錨＋1 潮鳴＋1 熔爐 | 43 /秒 | 2 發電機（40） | −3 | 300 ÷ 3 = 100 秒 ✅ | cap 22（升 2 級） |
| 加一座稜鏡 | 63 /秒 | 2 發電機（40） | −23 | 300 ÷ 23 ≈ 13 秒 ⚠️ 波次撐不完 | 儲槽線需 cap 28 才放得出 23 |
| 加一座稜鏡＋1 儲槽＋1 發電機 | 63 /秒 | 3 發電機（60） | −3 | 600 ÷ 3 = 200 秒 ✅ | cap 22 |

### 7.7 新手難度：靠關卡設計，不靠隱藏係數（★ 2026-07-27 改寫）

**原本的「新手係數」（塔待機耗能 ×0.6、敵人對建築傷害 ×0.7）已刪除。** 兩個理由：

1. **待機耗能已經是 0**（§7.4），×0.6 是空操作——R-4 的對策根本沒生效過。
2. **更根本的**：本作的核心就是「學會電力數學」。在教學期偷偷把物理改掉、第 6 關再無預警換回來，等於前五關教了玩家一個錯的模型。隱藏係數在這款遊戲特別有害。

**取而代之的硬性設計要求（寫入 B1.2 的 DoD）**：

> **戰役第 1–2 關必須以「新手可通關」為驗收條件**，且**只用關卡參數達成**，不得用隱藏乘數。

可用的關卡參數（全部是玩家看得見、學得到的東西）：

| 參數 | 說明 |
|---|---|
| 敵人數量與組成 | 前兩關只出漂蟲，數量少 |
| 波次數 | 前兩關波數短 |
| 礦點密度與距離 | 礦點多、離核心近 → 起手產能寬裕 |
| 核心距離 | 路徑短或長，決定塔的覆蓋壓力 |
| 跨越點座數 | 給得多＝網路好縫；給得少＝空間謎題 |
| 準備期 | **每關各自宣告**（§7.1 的 `PREP_TIME_TUTORIAL = 60s` 保留，但它是關卡參數不是隱藏係數——計時器就在畫面上） |

**難度層 1+ 的嚴苛係數不受影響**——那是玩家主動選擇、UI 明示的規則層（§3.11），不是偷偷改的。
