## 1. 願景陳述

> **你的生產線就是你的防線。**

玩家在一張有礦點與敵人路徑的地圖上，用**節點**與**導管**蓋出一套會自己運轉的生產網路；同一套網路同時餵養**塔（角色）**。塔不是蓋完就免費站著——**它持續消耗你的能量產出**。於是「防線再厚一點」與「產能再大一點」是同一條資源曲線的兩端，每一秒都在互相扣減。

**樂趣假設（G1 唯一驗收標準）**：
> 玩家會在波次倒數剩 40 秒時，明知有風險仍選擇再擴一條產線——並且在防線破掉之後想立刻重來一次。

**憲法級平衡哲學**（前期定死，生產期不重談）：

| # | 決策 | 內容 |
|---|---|---|
| B1 | 成長用**加法為主、乘法為輔** | 科技樹以「+2 吞吐」「+15% 效率」為主，禁止出現 ×2 以上的乘算堆疊，避免後期數值爆炸與平衡失控。 |
| B2 | **局外成長分兩軸，各有不同天花板** | **① 科技軸**（研究數據，只能靠遊玩取得）：全解鎖對戰鬥數值總增幅 ≤ **+35%**。<br>**② 等級軸**（tycoon 升級材料，可掛機／可加速取得）：塔與生產節點各 10 級，每級 +8%，滿級 **+80%**。<br>**硬性配套：等級軸的增幅必須被難度層同步吃掉**——難度層 N 的敵人強度縮放係數以「等級軸滿級」為基準校準。**等級軸買到的是「能挑戰更高難度層」，不是「碾壓現有內容」。**<br>局內只有臨時升級（隨局結束消失）。 |
| B3 | **競技分層：一榜純技術，一榜比戰力** | 每日挑戰跑**雙榜**，同種子、同地圖，只有起始配置不同：<br>**① 統一配置榜**——固定角色組、固定科技、固定等級；不論進度、抽卡或課金，所有玩家起始能力完全相同。<br>**② 自由配置榜**——玩家的完整戰力。<br>**統一配置榜永遠存在、永遠免費、永遠可爭第一。不得移除、不得收費、不得加入任何付費影響因子。**<br>**誠實註記**：第一版純離線（§3.10），兩榜實際上是本機最佳成績，沒有對手。**「對 P2W 的制衡」是接上線上榜之後才兌現的承諾**——在那之前它是架構保留，不是既成事實。不要在文案或對外說明中宣稱一個尚未存在的競技場。 |
| B6 | **賣速度，不賣次數，不賣進度** | F2P 變現只能**加快**既有路徑。所有內容與進度都必須能純靠遊玩取得（付費只是省時間）。<br>禁止：賣遊玩次數／體力（紅線 R2）、賣重試權、賣關卡解鎖鑰匙、**付費復活**（同時破壞 R1 與難度層／排行榜的意義）。 |
| B4 | **失敗只花時間** | 對應紅線 R1。任何失敗不扣除任何已獲得物。 |
| B5 | **不可暫停，但可跳過等待** | 戰鬥中固定 1× 速度。**準備期**可快進（跳過空等），戰鬥階段不可加速也不可減速。★ **B1.4.1：局內選單（ESC）也不暫停**——一顆可以隨時停下來慢慢想的鍵正是本條要擋掉的東西。選單面板上直接寫「時間仍在走」。 |

## 2. 核心循環

### 2.1 局內循環（一圈 60–120 秒）

```
        ┌──────────────────────────────────────────────────┐
        │                                                  │
        ▼                                                  │
  ①勘查 ──► ②拉線佈產 ──► ③資源流動 ──► ④【取捨】───┐      │
  讀地形     動詞：放節點    回饋：線變粗   擴產 or 築防  │      │
  找礦點     ＋連導管        數字上升                    │      │
  找路徑                                                 │      │
                                                         ▼      │
                              ⑦準備期修補 ◄── ⑥缺口暴露 ◄── ⑤波次來襲
                              45 秒可規劃      學習：哪條線      壓力：塔開火
                              可快進           不該那樣走        持續吃能量
                                     │                                 │
                                     └─────────────────────────────────┘
```

**每一步的時長與爽點**：

| 步驟 | 時長 | 爽點 |
|---|---|---|
| ① 勘查 | 15 秒（首波前） | 「這張圖的礦點分佈很刁鑽」的解謎感 |
| ② 拉線佈產 | 20–40 秒 | 線亮起、資源開始流動的即時回饋 |
| ③ 資源流動 | 持續 | **線的粗細會隨實際流量變化**——看得見自己的網路在呼吸。粗細在全圖可互相比較：同樣粗＝同樣流量，不管那條線升到幾級 |
| ④ 取捨 | 5–10 秒的決定 | **本作的心臟**。多一座塔＝少 8 能量/秒＝熔爐慢 20% |
| ⑤ 波次 | 20–40 秒 | 塔自動開火、能量條下探、線被打斷的緊張 |
| ⑥ 缺口暴露 | 即時 | 「早知道那條線該繞後面」的懊悔＝學習 |
| ⑦ 準備期 | 45 秒（可快進） | 修補、擴張、下注（提前召喚） |

### 2.2 外層循環（跨局）

```
打完一局 ──► 結算：研究數據＋稀有原料＋聲望
                │
                ├──► 科技樹（產能／防務／後勤三支）──► 下局起手更強、選擇更多
                ├──► 名冊（解鎖／抽卡新角色）────────► 下局玩法組合改變
                └──► 潮汐公司（tycoon，M2）─────────► 升級材料、招募券、藍圖槽、難度鑰匙
                                │
                                └──► 回到「再打一局」
```

### 2.3 長線留存的三根支柱

tycoon 已定位為**附屬補給站**而非獨立遊戲（§3.8），因此**留存不能靠「換個遊戲玩」**。三根支柱各自承擔不同的回訪動機：

| 支柱 | 回訪動機 | 節奏 |
|---|---|---|
| **成長曲線** | 「我的科技樹再推兩格就能解鎖那隻塔」 | 每次遊玩都在推進 |
| **每日種子挑戰** | 「今天的圖跟昨天不一樣，我想試試」 | 每天一次的新鮮理由 |
| **難度層精通** | 「上一層我差三波就過了」 | 卡關時的長期目標 |

**tycoon 的留存角色是「低壓力的短暫停留」**：打完一局進去收成、排下一批訂單、看著數字長，一兩分鐘就走。它降低關遊戲的動作成本，但它**不是**疲勞出口——真正的疲勞出口是**換一種塔防玩法**（戰役 ↔ 無盡 ↔ 每日挑戰，三種節奏完全不同）。

## 3. 系統清單

> **紀律**：每個系統都必須回答「服務核心循環的哪一步」。答不出來的進 backlog，不進 GDD。

### 3.1 流量網路（Flow Network）★核心
**服務循環步驟**：②③④　|　**里程碑**：M0

本作的自動化不是物件模擬（不搬運實體物品），而是**流量網路解算**。這是同時滿足效能、確定性、可讀性、極簡美術的唯一選擇。

**物件模型**：

| 概念 | 定義 |
|---|---|
| **節點 Node** | 地圖上的建築。有座標、生命值、輸入埠需求（demand）、輸出埠供給（supply）、內部處理速率。 |
| **導管 Line** | 連接兩節點的有向邊。有長度、吞吐上限（cap）、生命值、當前流量（flow）。 |
| **網路 Network** | 節點與導管構成的有向圖。每 tick 解算一次分配。 |

**解算規則**（純函式、零 RNG、確定性）：

1. 每 tick（0.1 秒）為一個解算週期。
2. 依資源種類分別解算（礦砂網、能量網、合金網互不干擾）。**解算順序固定為礦砂 → 能量 → 合金**：發電機的能量產出要乘自己的礦砂滿足率，熔爐的合金產出要乘自己那兩者中較低的一個。倒過來解會讓「上游缺料」延遲一個 tick 才傳到下游，玩家讀不出因果。
3. 每個消費節點聲明 `demand`，每個生產節點聲明 `supply`。
4. 沿圖做**容量受限的比例分配**：若某導管的請求總量 > `cap`，所有下游按**優先權加權**後等比例削減。
5. 消費節點拿到的量 < demand 時，以 `滿足率 = 實得/需求` 線性降低其產出或效能（**不直接停機**——避免全網崩潰的雪崩感）。
6. 解算完成後寫回每條導管的 `flow`，供視覺化使用。

**供不應求時的行為（重要設計決策）**：

當 `demand > supply` 時，本作**不停機，改為按比例降速**：`實際效能 = 標稱效能 × 滿足率`。

| 為什麼不停機 | 說明 |
|---|---|
| **停機會雪崩** | 能量不足 → 塔停火 → 敵人活更久 → 打壞更多導管 → 能量更少 → 全滅。玩家無法指出自己在哪一步輸的。降速是漸進的，玩家在 60% 效能下仍有搶救空間 |
| **降速可診斷** | 節點直接顯示「60% 飢餓」，玩家一眼知道缺口多大。停機只傳達「壞了」，不傳達「差多少」 |
| **與紅線一致** | R1「失敗只花時間」隱含「玩家要能看懂自己為什麼輸」。雪崩式崩潰違反這一點 |

> **真實工廠確實是批次運作**（湊不滿一批就停機）。本作刻意不模擬這一點——那是寫實感的代價，而我們要的是可讀性與可救性。

**★ 能量是流率，不是水池**（2026-07-27 定案）：

**沒有全域能量池。** 每 tick 的供給與需求就地結算，能量不會自動累積在某個看不見的帳戶裡。**唯一的儲存體是儲槽節點，它有座標、有導管、有射程外的距離。**

| | 決策 |
|---|---|
| 頂欄顯示 | `能量 40/63 ⚠`＝**本 tick 供給／需求**（滿足率 63%）。不是存量／容量。 |
| 儲槽顯示 | 另列 `儲槽 340/600`＝全部儲槽的充能總和／總容量。 |
| 儲槽解算語意 | 全網盈餘時它是**消費者**（充能，吃優先權權重）；赤字時它是**供給者**（放電）。充放電速率**受它自己那條導管的 `cap` 約束**——這是它與全域水池的根本差別。 |

**為什麼不做全域水池**：水池不需要管線送電，於是儲槽變成「+300 容量」的被動配件，蓋在地圖哪個角落都一樣。那會同時廢掉三件事——儲槽的「核心策略建築」定位、導管加粗的取捨（§7.2）、以及「你的生產線就是你的防線」這個空間論述。**儲槽放遠了、幹線沒加粗，它的電就趕不到稜鏡那裡**，這正是我們要的。

**★ 不變量：網路永不全域死鎖。**
**採集器沒有任何輸入需求**（只要蓋在礦點上就出礦）。因此網路永遠存在一個不依賴任何其他節點的源頭，結構上不可能出現「A 等 B、B 等 A」的全域凍結。
**任何新增的生產節點都不得破壞此不變量**——若未來要加入「需要能量才能採礦」的節點，必須同時保留至少一種零輸入的採集手段。

**優先權面板（本作最重要的 UI 元件）**：
玩家為**每一種節點類型**（錨／稜鏡／潮鳴／回收者／熔爐／儲槽／…）設定 1–5 的優先權。**當能量不足時，優先權決定誰先餓死：塔停火，還是熔爐停產。** 這把「痛苦的取捨」做成一個玩家隨時可以拉的滑桿——它不是選單設定，它是戰術動作。

**★ 為什麼是「依類型」而不是「依節點」**（2026-07-27 定案）：

1. **戰術動作必須是一個手勢。** 遊戲不可暫停。滑桿永遠在同一個位置＝一個手勢；在地圖上找到那顆節點再拖它＝兩三個手勢。依節點會把最重要的戰術動作變成操作負擔（R-1）。
2. **操作負擔必須恆定。** 依節點的話，蓋 20 座塔就有 20 條滑桿要管——每蓋一座建築就多一個要顧的東西，這是操作負擔的滑坡。依類型永遠是 5–8 條。
3. **依節點解的是耗能模型已經解掉的問題。** 待機耗能為 0，沒開火的塔本來就不吃電；「這座稜鏡比那座重要」只在兩座都在交戰時才存在，而兩座都在交戰就代表兩座都有敵人要打。單體差異已由每座塔各自的**目標選擇**（§3.3）承擔。
4. 面板恆為 5–8 條，44×44 px 觸控命中區放得下（`20_ART_DIRECTION.md` §1.3b P2）。

**儲槽在優先權面板佔一格**：盈餘時它是可調的低優先權消費者（充能搶不搶得贏熔爐），赤字時它是供給者。這讓「這一波要不要留電」成為一個戰術決定。

**可讀性規範**（風險 3 的對策，硬性要求）：
- 導管**粗細 = 實際流量 ÷ 全遊戲最大 cap**（★ B1.1.1 改；原本分母是「這條線自己的 cap」＝飽和度）
- 導管**顏色**：正常（青）／飽和（亮青，滿載）／飢餓（暗青閃爍）
- 節點三態徽章：`缺料` / `滿溢` / `正常`
  - **`正常` 不畫任何東西**（★ B0.6 定案）。徽章是**例外標記**：一屏 14 個節點全部掛上「我很好」的圖示，等於把要找的那兩個異常埋進 14 個雜訊裡——那正好與 R-3「一眼看出瓶頸」相反。三態仍是三態，只是第三態的視覺編碼是「乾淨」。
  - `缺料`＝**它要的東西沒到齊**（滿足率 < 95%）：節點上方一個橙色**倒三角**（空的、往下）。
  - `滿溢`＝**它產得出來但送不掉**（本 tick 有推不出去的餘量）：節點上方一個青色**正三角**（滿的、往上）。這是「導管被打斷」在地圖上唯一的即時說法——B0.4 只有頂欄的 `▲0.0/秒`，玩家看得到結果卻找不到位置。
  - **兩態各自只掛在「跟它有關」的節點上**：`缺料` 只給**自己宣告過需求**的（熔爐、交戰中的塔、發電機的燃料），`滿溢` 只給**自己產得出東西**的（採集器、發電機）。核心的礦砂需求（收剩下的）與儲槽的充能需求（有多少收多少）是解算器合成的**機會性需求**，中繼手上塞著的餘量則是路由後果——照字面掛上去，這三種會在正常遊玩中恆亮，例外標記就退化成背景雜訊。
- **驗收標準（★ 執行方式已定案）**：以 **`TL_NAKED=1`** 產出**隱藏全部數值標籤**的截圖——只留線寬、顏色、三態徽章——交 Opus 5 指認瓶頸節點，答對才算過。
  *為什麼不是「找個未受訓玩家」*：本案沒有這個人（樂趣與首次體驗由使用者本人判，而他是設計者；agent 只驗程式碼與可讀性）。而拿**有數字**的截圖問 agent 一定會過——它答對的是「我讀得懂 `能量 40/63`」，不是「線寬與顏色在傳達資訊」。遮掉數字才驗得到真東西。詳見 `30_TECH_DESIGN.md` §4.1、`50_QA_PLAN.md` §0.1。

### 3.2 建造系統
**服務循環步驟**：②⑦　|　**里程碑**：M0

- **放置**：從建造面板選節點類型 → 地圖上點擊放置。網格對齊（32px）。
- **連線**：**從起始節點按住左鍵 → 拖到目標節點放開 → 生成導管**。可經中繼節點轉折。
  - **★ 拖曳是唯一的拉線方式，沒有「連線」模式**（B1.6.2 導入拖曳，B1.3.1 移除模式鈕）。按在既有節點上時，該次點擊延到放開才判定：放開在另一個節點上＝拉線，放開在原地＝該模式原本的動作。理由：真正的建造節奏是**蓋一個 → 接一條 → 蓋一個 → 接一條**（第 1 關的參考解就是 6 蓋 6 接交替），每一步都往返左欄等於在最頻繁的動作上加 10 次無決策的點擊。留一顆只能點兩次的模式鈕，等於在教一個比較慢的做法。
- **模式只有三個**：建造（選了哪一種建造鈕就是哪一種）、加粗、拆除。**平移不是模式**——按住滑鼠中鍵拖（B1.3.1，使用者指定）。模式的代價是「忘記切回來時點地圖沒反應」，而平移頻繁到會天天付這個代價。
- **建造鈕上只寫名字，不寫價**（B1.3.1，使用者指定）：價牌在提示列的第一行，滑鼠停在鈕上時圖鑑浮層也會寫一次。同一個數字印三遍只是把鈕撐長。
  - **★ 選好起點後，地圖上畫出八條方向導引線**（水平／垂直／四個 45°），並依合法性把預覽線染成綠／橙，提示列同步說明差在哪（「橫 4 直 3，要走 45° 兩邊得一樣長」）。**理由**：規則本身沒問題，難的是用肉眼在網格上找出正斜角——使用者實玩後回報「沒有辦法 45 度放置管道」。**一條規則如果只能靠試錯才知道自己有沒有踩中，它在體感上就等於壞掉。**
- **成本**：節點有固定造價；導管造價 = `長度(格) × 單位成本`。
- **即時預覽**：拖曳中顯示「這條線會帶來 +X/秒」與「總耗能將變為 Y/秒」。**這是把取捨資訊在決策前就攤開給玩家看**，不讓玩家事後才發現餓死了。
- **拆除**：返還 50% 成本。
- **禁止事項**：不可在敵人路徑格上建造**節點**（路徑是既定的，玩家不能封路——這不是迷宮塔防）。

#### ★ 跨越點（橋）— 路徑上唯一可鋪管的地方

地圖作者在敵人路徑上指定若干**跨越點**。規則：

| 項目 | 規則 |
|---|---|
| 可鋪 | **導管**可以鋪過跨越點 |
| 不可鋪 | **節點**（含中繼）一律不可——它們會擋路 |
| 安全性 | **橋是架高的 → 橋上的導管不受敵人攻擊**（§3.5） |
| 數量 | 由地圖作者決定，是**關卡設計的主要刻度尺**——一座橋的圖跟四座橋的圖是兩款遊戲 |

**設計意圖**：路徑把地圖切開，跨越點決定你的網路能怎麼縫回去。橋是安全動線，所以「該不該為了短路而貼著路徑走」這個取捨仍然存在（貼路的線會被打，§3.5），但玩家永遠有一條可規劃、不會被打斷的幹線選擇。這同時避免了「唯一通路被打斷 → 整側斷電」的雪崩，與 §3.1 的反雪崩原則一致。

**視覺**：跨越點在地圖上明示（見 `20_ART_DIRECTION.md` §1.6），玩家不需要試錯才知道哪裡能過。

### 3.3 塔（角色）系統 ★
**服務循環步驟**：④⑤　|　**里程碑**：M0

**塔即角色**：每個角色是一種可放置的防禦建築，**全自動開火**，射程內即攻擊，玩家不下達戰鬥指令。

**通用屬性**：

| 屬性 | 說明 |
|---|---|
| 造價 | 礦砂／合金 |
| **交戰耗能** | **射程內有目標時，每秒持續消耗能量**（與射速無關） |
| **待機耗能** | **預設 0**——射程內無敵人時幾乎不耗電。少數提供持續全域效果的特殊角色例外（未來設計時逐一標註） |
| 射程／射程形狀 | 圓形／扇形／直線 |
| 傷害類型 | 物理（被護甲減免）／能量（被屏障減免） |
| 目標選擇 | 最近／最前／最高血量／最低血量（玩家可設）。**M0 只實作「最前」（路徑進度最大者）並且沒有選單**——四選一是操作品質，不是核心取捨，排到後勤科技（§3.6）一起做 |
| 特殊機制 | 每個角色獨有 |

#### ★ 耗能模型：峰值約束，不是平均約束

塔**只在交戰時耗電**。這把核心取捨從「持續扣血」變成**尖峰衝擊**：

```
準備期（45 秒）        波次期（20–40 秒）
塔耗能 ≈ 0             全部塔同時開火 → 耗能暴增
生產線滿速運轉          生產線被塔搶電 → 產能驟降
儲槽充能 ↑↑            儲槽放電 ↓↓
```

**這條規則的三個後果**（全部是設計意圖，不是副作用）：

1. **儲槽 Silo 從「緩衝配件」升格為核心策略建築。** 你在準備期充能、波次期放電。儲槽容量直接決定你能養幾座塔。
2. **約束變成「峰值電力」而非「平均電力」。** 多蓋一座塔的代價不是持續的漏電，而是**波次期的電力缺口更大** → 你必須擴發電或擴儲槽 → 那些資源就不能拿去擴礦。取捨完好無損，只是換了發生的時刻，而且更戲劇性。
3. **提前召喚變得更兇。** 提前開波 = 提前讓工廠停擺、提前開始燒儲備電。下注的張力提高。

**能量不足時的行為**：射速按滿足率**線性下降**（滿足率 60% → 射速 60%），不會完全停火（理由見 §3.1 供不應求）。潮鳴的光環強度同樣按滿足率縮放。

#### ★ 全域規則：擊殺回收

**任何塔擊殺敵人，都回收該敵人價值 25% 的礦砂。** 這是全域規則，不是特定角色的能力。

設計意圖：讓防禦本身帶有經濟回饋，緩和「多蓋塔 = 純虧」的直覺，並讓高擊殺效率的佈局自然獲得經濟優勢。

> **★ 回收的礦砂直接入帳，不走導管**（B0.5 拍板）。它是塔在擊殺處撿到的殘骸，不是採出來要運回核心的礦——採集器的產出才需要接線入帳（§7.3）。
>
> **這條不對稱是模型逼出來的，不是便宜行事**：礦砂有一個全域帳戶（核心就是礦砂銀行），所以撿到的礦砂有地方可去；**能量沒有帳戶**（§3.1 無全域能量池），所以回收者回收的能量**只能從它自己那條導管注入**，見 §7.4。同一條規則落在兩種資源上，長相不同是因為兩種資源的儲存語意本來就不同。

#### ★ 礦砂↔能量匯率：**1 礦砂 = 5 能量**

敵人的「價值」（§7.5）以**礦砂**計。任何把價值換算成能量的地方一律用這個匯率，它不是新發明的數字——它就是發電機的轉換比（§7.3：4 礦砂/秒 → 20 能量/秒）。目前唯一的用處是回收者的能量回收。

**M0 四隻角色**（覆蓋四種戰術定位，足以驗證核心取捨）：

| 角色 | 定位 | 傷害型 | 特色 | 設計意圖 |
|---|---|---|---|---|
| **錨 Anchor** | 基礎 | 物理 | 短射程、高單體傷害、**交戰耗能低** | 便宜可靠的地基。教會玩家「開火才要錢」的成本概念。 |
| **稜鏡 Prism** | 爆發 | 能量 | 直線穿透雷射，可同時打穿一整列敵人、**交戰耗能極高** | 取捨的極端案例：一座稜鏡開火時 ≈ 五座錨。它讓儲槽容量成為硬需求。 |
| **潮鳴 Knell** | 控場 | 無傷害 | 範圍減速 −40%、破甲 −25%，交戰耗能中 | 證明「不造成傷害的建築也值得佔用電力」。光環僅在射程內有敵人時啟動（＝交戰狀態）。**★ 硬性要求（B1.8）：它必須有非開火的視覺回饋**——`rof = 0` 代表它永遠不產生開火線也不播開火音，而它每秒吃 9 能量。一座看不出自己在工作的塔，等於把「交戰時每秒吃電」這條全案的心臟藏起來。畫法見 `20_ART_DIRECTION.md` §1.6。 |
| **回收者 Reclaimer** | 經濟 | 物理 | 中等傷害，**射程內任何敵人死亡（不限自己擊殺）即回收其價值 60% 為「能量」注入電網**（匯率 1 礦砂 = 5 能量，見上） | **打破峰值約束的鑰匙**：唯一能在波次進行中補充電力的塔。因為算的是「射程內的死亡」而非「自己的擊殺」，它的擺放是一道空間謎題——要放在殺戮最密集處，而不是它自己射得最爽的地方。長波次與無盡模式的核心建築。 |

> **回收者的定位為何改變**：既然「擊殺回收礦砂」已成為全域規則（見上），原本的「回收礦砂 30%」失去獨特性。改為**回收能量**後，它直接對抗新耗能模型製造的峰值缺口——這使它成為長波次的關鍵解答，且與礦砂經濟不重疊。

**擴充角色**（M2 起，見 §5 內容矩陣）：目標 24 隻，其中 6 隻為抽卡專屬稀有角色。

### 3.4 波次與壓力系統
**服務循環步驟**：⑤⑦　|　**里程碑**：M0

- **波次表**：每關預先定義的敵人組成序列（戰役手作，無盡程序生成）。**確定性**：同種子必同波次。
- **準備期**：波與波之間 45 秒安全窗口（戰役第 1–5 關為 60 秒）。**時間與生產持續流動**，只是沒有敵人。可快進。
- **提前召喚**：準備期內任意時刻可按下，立即開波。
  - 獎勵倍率 = `1 + (剩餘秒數 / 準備期總長) × 0.5`（最高 +50%）
  - 獎勵形式：該波掉落的礦砂與研究數據按倍率增加
  - **設計意圖**：把取捨從「被動承受」變成「主動下注」。這是分數天花板的主要來源，也是高手與新手的分野。

### 3.5 敵人系統
**服務循環步驟**：⑤⑥　|　**里程碑**：M0

- **行為（★ walk-by，2026-07-27 定案）**：敵人沿預定路徑推進，**永不停步**。每 tick 對**相鄰 1 格內**的玩家建築造成其「對建築傷害」，然後繼續走。**只有核心會讓它們駐足**（停下來打到核心歸零）。
- **例外**：**跨越點（橋）上的導管不受攻擊**——橋是架高的（§3.2）。

> **★ 免疫範圍含引道**（B0.4 實作時補齊）：免疫的不只是跨越點那一格，而是**跨越點 ±1 格**——也就是導管上橋與下橋的兩段引道。
>
> **不這樣做的話這條規則等於不存在**：敵人走在路徑格上，破壞半徑 1 格。導管要垂直穿過路徑，就必然佔用「路徑格（橋）＋兩側各一格」，而那兩側正好都在破壞半徑內。只免疫橋面那一格的話，**每一條過橋的線都會在引道被打斷**，橋就從「又短又安全的路」變成純裝飾。
>
> 這也正是 `20_ART_DIRECTION.md` §1.6 已經畫出來的樣子——橋面兩端本來就伸出格外，引道是那個架高結構的一部分。
- **為什麼不做「停下來攻擊」**：一旦敵人會為建築駐足，玩家就會發現丟一排 15 礦砂的中繼是最便宜的拖時間道具——那等於把**迷宮塔防**偷裝回來（它在砍案清單上），而且波次長度變得不可預測，提前召喚的下注也算不清。walk-by 沒有索敵邏輯、沒有停頓、波次長度恆定。
- **關鍵設計**：**敵人會打斷你的線。** 這讓佈局有了空間策略——貼路徑走的線短、便宜、危險；退開一格就安全但長、貴；橋是唯一又短又安全的路，而橋有幾座是地圖作者決定的。沒有這一條，塔防就只是「保護一個點」。
- **塔的擺位**：塔的射程 4–9 格遠大於 1 格的破壞半徑，所以塔可以站在安全距離外開火。**願意把塔（或線）壓到路邊，換的是覆蓋率與長度，賭的是它撐不撐得住。**
- **屬性**：

| 屬性 | 效果 | 剋制方式 |
|---|---|---|
| 護甲 Armor | 物理傷害 −N | 能量傷害、潮鳴破甲 |
| 屏障 Barrier | 能量傷害 −N% | 物理傷害 |
| 迅捷 Swift | 免疫減速 | 高爆發單體 |

- **失敗條件**：核心生命歸零 → 本關失敗 → 可立即重來（**無任何損失**，紅線 R1）。

### 3.6 科技樹
**服務循環步驟**：外層　|　**里程碑**：M1

三支路線，用**研究數據**解鎖：

| 路線 | 內容 | 上限 |
|---|---|---|
| **產能** | 導管吞吐、採集速度、熔爐效率、儲槽容量 | 合計 +35%（B2） |
| **防務** | 塔傷害、射程、**交戰耗能效率**（最重要的一項） | 合計 +35%（B2） |
| **後勤** | 藍圖槽數量、優先權精度、建造返還率、預覽資訊深度 | 無數值上限（純便利性） |

**設計意圖**：後勤支不給數值，只給**操作品質**——這是對「不可暫停可能變手速」風險的長線解藥：玩得越久，操作負擔越低，思考空間越大。

### 3.8 潮汐公司（tycoon）— 塔防的後勤補給站
**服務循環步驟**：外層供給　|　**里程碑**：M2

> **定位（2026-07-27 修訂）**：tycoon **不是**可獨立遊玩的第二個遊戲，而是塔防的**附屬資源供應系統**。
> 它的存在理由只有一個：**穩定供給塔防所需的資源與升級材料**。任何「讓 tycoon 本身變得好玩到可以取代塔防」的提案一律進 backlog。

**核心循環**（刻意保持單薄）：
```
接訂單（品項、數量、交期、報酬）
  → 排產線（複用流量網路引擎，無敵人、無時間壓力）
  → 生產累積（在線即時／離線掛機）
  → 交貨結算 → 資金與材料
  → 擴廠（產線位）／研發（新品項）
  → 接更大的訂單
```

**產出（全部流向塔防）**：

| 產出 | 用途 |
|---|---|
| 資金 Credit | 兌換以下各項 |
| 升級材料 | 塔的等級、生產節點的等級（**數值強化**） |
| 招募券 | 名冊招募 |
| 藍圖槽、難度鑰匙、外觀 | 橫向內容 |

**掛機規則**：離線時持續生產，受**倉儲上限**約束（滿了停產）。倉儲上限可升級。
**這不是體力閘門**（紅線 R2）：它不限制你能玩幾局塔防，它是「回來收成」的正向設計。塔防隨時可以玩，不需要任何 tycoon 產物。

**塔防 → tycoon 的回流**：塔防局掉落的稀有原料可加速高階訂單。tycoon 也能自行採購（較貴），因此**掛機路線與遊玩路線都走得通**。

**設計約束（防止它膨脹成第二個遊戲）**：
1. tycoon **沒有失敗狀態**、沒有時間壓力、沒有對手。它是水龍頭，不是挑戰。
2. tycoon 的 UI 深度上限：**兩個畫面**（訂單板＋產線編輯）。超過就是膨脹。
3. tycoon 的任何新機制都必須回答「這如何讓塔防更好玩」。答不出來就不做。
4. 市場價格波動、人事系統、股價、競爭對手、員工士氣 → **永久 backlog**。

**M2 第一版範圍**：只做「訂單 → 產線 → 交貨 → 擴廠」單一循環。

### 3.9 名冊與招募
**服務循環步驟**：外層　|　**里程碑**：M2

- **確定性解鎖**（主要途徑，18 隻）：科技樹、戰役關卡獎勵、成就、商店直購。玩家能規劃「我再推兩關就能拿到那隻」。
- **招募（抽卡）**（6 隻稀有角色）：用聲望券抽「潮汐名冊」。
  - **不重複**：抽到的必定是尚未擁有的稀有角色。隨機的是**順序**，不是有沒有。
  - **有畢業**：UI 常駐顯示「還剩 N 隻未收集」。抽完即畢業，不再消耗券。
  - **不使用賭博語彙**：無十連演出、無稀有度金光、無「差一點就中」的假張力。
  - **不影響統一配置榜**：該榜使用固定角色組，抽卡結果完全不進入（B3）。自由配置榜才會反映。
- **聲望券來源**：戰役里程碑、成就、tycoon 產出、無盡分數門檻，**以及付費購買**。
- **B6 保障**：6 隻稀有角色**全部都能純靠遊玩取得**（券的產出速率保證在合理時間內可畢業），付費只是加快。不存在「只能課金拿到」的角色。

### 3.10 排行榜與每日挑戰
**服務循環步驟**：長線引擎　|　**里程碑**：M2

- **每日挑戰**：全球同一固定種子（`seed = hash(日期)`）。**同一張圖跑兩榜**：

| 榜 | 起始配置 | 目的 |
|---|---|---|
| **統一配置榜** | 固定角色組、固定科技、固定等級、固定起始資源。**與玩家的任何進度與課金完全無關** | 純技術競爭。免費玩家爭第一的舞台。**對 P2W 的唯一制衡（B3）** |
| **自由配置榜** | 玩家的完整戰力（自選角色、自己的科技與等級） | 成長曲線的展示場；付費的兌現點 |

- **實作成本極低**：兩榜共用同一套地圖、波次、模擬與計分，差異只在 `SessionState` 的初始化參數。**不得為此拆成兩套邏輯。**
- **第一版純離線**：本機保存每日兩榜的最佳成績與歷史紀錄。**誠實註記**：離線狀態下兩榜是兩個本機數字，沒有排名、沒有對手。雙榜架構此時的價值是**接線上榜時零改動**，不是「已經在制衡 P2W」（B3）。
- **架構要求**：分數、局面、操作序列全程可序列化、可重現（見 `30_TECH_DESIGN.md` §2 確定性）。日後接線上榜**不需重寫核心**。
- **無盡模式**：程序生成地圖 + 無限波次，個人最佳紀錄（自由配置）。

### 3.11 難度層
**服務循環步驟**：長線引擎（深度精通）　|　**里程碑**：M3

通關戰役後解鎖，逐層疊加更嚴苛的規則（例：塔交戰耗能 +20%、敵人破壞導管速度加倍、準備期縮短為 30 秒）。共 12 層。成本極低（純數值與規則開關），是深度精通的主要載體。

**★ 難度層同時是等級軸的配重**（B2 ②）：每層的敵人強度縮放係數**以「等級軸滿級」為基準校準**，因此買到滿級不會碾壓既有內容，而是讓你有資格挑戰下一層。這是本作處理 P2W 數值膨脹的主要機制（`00_CONCEPT.md` 風險 6）。

**防通膨機制**：
- 局內資源（礦砂／能量／合金）**每局歸零**，不跨局累積 → 結構上不可能通膨。
- 研究數據：科技樹總量有限（B2 上限 +35%），走滿即封頂。
- 資金：tycoon 的擴廠成本呈**指數上升**（×1.35/級），配合線性收入增長，形成自然的收斂曲線。
- 聲望券：抽卡池僅 6 隻且不重複，抽完畢業 → 券的需求有明確終點。

### 4.2 成長曲線公式

| 對象 | 公式 | 說明 |
|---|---|---|
| 科技樹節點成本 | `cost(n) = 50 × n^1.6` | n = 該支已解鎖數。前期便宜、後期需要多局累積。 |
| tycoon 擴廠成本 | `cost(L) = 500 × 1.35^L` | L = 當前廠等。 |
| tycoon 訂單報酬 | `reward(L) = 120 × L^1.25` | 線性偏下，配合指數成本形成收斂。 |
| 無盡波次強度 | `hp(w) = 100 × 1.11^w`，`count(w) = 4 + floor(w/3)` | 指數血量 + 線性數量。玩家產能需同步指數成長才撐得住 → 天然的技術檢定。 |
| 局末研究數據 | `data = 10 × 波次數 + 2 × 產能積分 + 提前召喚加成` | 產能積分 = 全局平均每秒總產出 / 10 |

### 4.3 局內臨時升級

局內可用礦砂即時升級單座建築（+1 級，最多 3 級），**隨局結束消失**（B2）。這給予局內的短期成長回饋，同時不污染跨局平衡。

**HUD 設計硬性要求**：
1. **能量列是全畫面最醒目的元件**——它是取捨的化身。顯示的是**本 tick 供給／需求**（滿足率），不是存量／容量（§3.1）；滿足率下探時整列變色並脈動。
   - **★ 能量列是一條圖形，不是一串數字**（B0.6 定案）：琥珀實心＝供給、右側橙色缺口＝短少的部分、細刻度＝需求位置。因此它**在 `TL_NAKED=1` 下要留著**——`TL_NAKED` 遮的是「數值標籤」，一條長度即資訊的橫條屬於線寬／顏色那一類，遮掉它等於把 R-3 要驗的東西一起遮掉。條上的數字才遮。
2. **建造預覽必須在決策前顯示總耗能變化**，不讓玩家事後才發現餓死。
3. **提前召喚按鈕常駐顯示當前獎勵倍率**，讓下注的誘惑一直在眼前。
4. 準備期與戰鬥期的**畫面色調不同**（準備期偏冷靜的青、戰鬥期加入警示暖色），讓玩家不必看計時器也知道自己在哪個階段。
5. **浮層不得遮住路徑與跨越點**。面板可收合；收合狀態下地圖 100% 可見。
6. **所有面板項目的觸控命中區 ≥ 44×44 px**（`20_ART_DIRECTION.md` §1.3b P2）。這是把面板改成浮層／抽屜的直接原因之一——固定窄欄塞不下 9 個 44px 的建造項目。

> **★ 導管無方向**（B0.5 補上）。B0.3–B0.4 的實作只給一個方向，而那個方向是
> **玩家先點了哪個節點**——畫面上完全看不見，玩家也無從選擇或修正。
>
> B0.5 才讓它現形：塔是末端消費者，「先點塔、再點幹線」是最自然的手勢，
> 拉出來的線卻只能從塔往外送電，於是那座塔**永遠是 0 電**，而畫面上那條線
> 看起來一切正常。看不見、控制不了、又會靜靜毀掉整套佈局的東西不是規則，是缺陷。
>

**★ 走向限制的來源**：`20_ART_DIRECTION.md` §0 已經把「秩序側＝直線、90°/45° 轉折」寫成核心視覺命題。任意角度的導管會直接違反它，也會讓「中繼＝轉折器」這個 15 礦砂的便宜零件失去存在理由。**限制走向不是簡化，是讓中繼這個節點有意義。**

*（`cap` 每種資源各自計是 B0.3 的實作決定：混線在實際打法裡罕見——採集器線走礦砂、發電機線走能量，兩者本來就不共用。若日後出現有意義的混線玩法，再改為共用額度。）*

**★ 基礎 cap 10 小於發電機輸出 20，這是設計，不是漏洞**（2026-07-27 定案）：

你蓋的第一台發電機，有一半的電出不來——那條線會立刻滿載變色（§3.1 可讀性規範）。**遊戲用你蓋的第二個建築教你讀瓶頸**，正好是 R-3 要驗的能力。要送滿一台發電機得把幹線升 2 級（20 + 40 = 60 礦砂，剛好一台發電機的價錢）——**加粗幹線本身就是一個和「多蓋一座採集器」競爭的取捨**。

*（科技樹「導管擴容 I/II/III」加的是**基礎** cap +2/+2/+2 → 16，與局內升級疊加，滿配 34。）*

**★ 2 級起要合金，1 級不要**（B1.1 定案）：加粗到 2 級是「送滿一台發電機」的門檻，也是上表唯一被 M0 教學實際用到的一級——**把它鎖在合金後面，等於把 B0.3 教會玩家讀瓶頸的那個動作鎖掉**。所以 1 級維持純礦砂，2/3 級才要合金。

它換來的是：**幹線的後半段升級與塔共用同一份合金**——熔爐每秒吃 8 礦砂 ＋ 10 能量（半台發電機）才產出 2 合金/秒，於是「加粗幹線 vs 蓋碎浪」變成核心取捨在第三種資源上的同一句話。合金不是新的進度條，是同一個取捨的第二個實例。

**★ 三條在 B0.5 實作時補齊的規則**（原表未寫，照字面實作會產生歧義）：

|---|---|---|

| 熾泳 | 22 礦砂 | **66** |
| 甲殼 | 30 礦砂 | **90** |

*校準基準*：回收者一波耗 7 × 30s ＝ 210 能量。射程內死 10 隻（均價 20 礦砂）＝ 回收 600 能量，淨 +390 ≈ 0.65 台發電機——不吃礦砂燃料，但要靠擊殺密度。**條件式強勢，形狀健康**。若實測回收者變成必蓋或廢物，先動的是 60% 這個數字，不是匯率。

> **★ 回收的能量是一個緩衝，經回收者自己那條導管以 `cap` 限速注入**（B0.5 拍板）。它**先供自己的交戰耗能**，剩下的才推進電網。
>
> **為什麼不能瞬間到帳**：能量沒有全域帳戶，而「唯一的跨 tick 儲存體是儲槽，且充放電受它自己那條導管的 `cap` 約束」是鎖定的設計。一次擊殺回收 36–90 能量瞬間注入全網，等於在回收者身上偷開了第二個水池。**與儲槽同構處理**是唯一不破壞模型的做法：回收者的線因此成為一個真正的瓶頸，加粗它要和「多蓋一座採集器」競爭——這正是本作要的形狀。
>
> **對上面校準基準的影響（已知、待 B1.3 實測）**：基礎 `cap` 10 的線，一波 30 秒最多只推得出 **300** 能量，低於基準假設的 600。回收者因此是「**擊殺密度 × 導管粗細**」的雙重條件，比原本更難用、也更有得選。這個交互作用留到 B1.3 平衡批次用 headless 模擬實測，**先不動 60%**。
>
> **緩衝上限 100 能量，滿了溢流丟棄。** 沒有上限的話回收者就是**第二座儲槽**——一座沒有容量欄位、沒有造價、也沒被列進優先權面板的儲槽，正是「無全域能量池」要擋掉的東西。100 剛好裝得下單次最大的一筆回收（甲殼 90），所以一發大的永遠不會溢流，一連串的才會。推不出去的電本來就沒人用得到，丟棄不損失任何玩家做得到的事。

**能量不足時**：`實際射速 = 基礎射速 × 滿足率`，滿足率 = 實得能量/需求能量。潮鳴的光環強度同樣按滿足率縮放。

**峰值電力參考算式**（設計數值時的校準基準）：

> **前提：本表假設幹線導管已升到足夠 cap**（§7.2）。基礎 cap 10 送不出 20/秒的發電機輸出，也放不出 23/秒的儲槽缺口——**加粗幹線的礦砂成本要算進下表的每一列**。

| 情境 | 波次期峰值耗能 | 發電配置 | 缺口 | 儲槽支撐時間 | 幹線需求 |
|---|---|---|---|---|---|
| 早期：4 錨 | 16 /秒 | 1 發電機（20） | 盈餘 +4 | — | cap 16（升 1 級） |
| 中期：6 錨＋1 潮鳴＋1 熔爐 | 43 /秒 | 2 發電機（40） | −3 | 300 ÷ 3 = 100 秒 ✅ | cap 22（升 2 級） |
| 加一座稜鏡 | 63 /秒 | 2 發電機（40） | −23 | 300 ÷ 23 ≈ 13 秒 ⚠️ 波次撐不完 | 儲槽線需 cap 28 才放得出 23 |
| 加一座稜鏡＋1 儲槽＋1 發電機 | 63 /秒 | 3 發電機（60） | −3 | 600 ÷ 3 = 200 秒 ✅ | cap 22 |

**這張表就是核心取捨的數學形狀**：多一座稜鏡，你得補一台發電機＋一座儲槽（＝110 礦砂＋持續 4 礦砂/秒的燃料）＋把幹線再加粗，那些資源本來可以拿去多蓋一座採集器。

### 7.6 波次與獎勵

| 項目 | 公式／值 |
|---|---|
| 無盡波次血量 | `hp(w) = base × 1.11^w` |
| 無盡波次數量 | `count(w) = 4 + floor(w/3)` |
| 提前召喚獎勵倍率 | `1 + (剩餘秒數 / PREP_TIME) × 0.5`，上限 1.5 |
| 局末研究數據 | `10 × 波次數 + 2 × 產能積分 + 提前召喚累計加成` |
| 產能積分 | `全局平均每秒總產出 / 10` |

**★ 上表三個數字的可執行定義（B0.6 補，原文只給了公式骨架）**：

| 詞 | 定義 | 為什麼是這樣 |
|---|---|---|
| **提前召喚累計加成** | `Σ 每波 10 × (該波倍率 − 1)`，每波最多 +5 | 「獎勵形式：該波掉落的礦砂與研究數據按倍率增加」（§3.4）。研究數據裡屬於「該波」的項就是 `10 × 波次數` 的那 10 點，倍率直接乘在它上面；攤開來就是這一行。不另發明係數。 |
| **該波倍率** | 按下提前召喚**當下**算一次，鎖給那一波 | 波次進行中準備期倒數已經停了，事後再算會拿到 0。鎖住的另一個好處：玩家按下去就知道自己賭到多少。 |
| **總產出** | **送達核心的礦砂累計**（不是採出來的量） | 與 `▲/秒` 同一個口徑（§7.3 核心＝礦砂銀行）。採了卻運不回去的礦砂不算產能——那正是 `滿溢` 徽章要指出來的事。 |
| **平均每秒** | `累計 ÷ (tick 數 × 0.1)`，含準備期 | 準備期也在生產，把它排除等於獎勵「一直快進」。 |

### 7.7 新手難度：靠關卡設計，不靠隱藏係數（★ 2026-07-27 改寫）

**原本的「新手係數」（塔待機耗能 ×0.6、敵人對建築傷害 ×0.7）已刪除。** 兩個理由：

1. **待機耗能已經是 0**（§7.4），×0.6 是空操作——R-4 的對策根本沒生效過。
2. **更根本的**：本作的核心就是「學會電力數學」。在教學期偷偷把物理改掉、第 6 關再無預警換回來，等於前五關教了玩家一個錯的模型。隱藏係數在這款遊戲特別有害。

**取而代之的硬性設計要求（寫入 B1.2 的 DoD）**：

> **戰役第 1–2 關必須以「新手可通關」為驗收條件**，且**只用關卡參數達成**，不得用隱藏乘數。

可用的關卡參數（全部是玩家看得見、學得到的東西）：

| 參數 | 說明 |
|---|---|
| 敵人數量與組成 | 前兩關只出漂蟲，數量少 |
| 波次數 | 前兩關波數短 |
| 礦點密度與距離 | 礦點多、離核心近 → 起手產能寬裕 |
| 核心距離 | 路徑短或長，決定塔的覆蓋壓力 |
| 跨越點座數 | 給得多＝網路好縫；給得少＝空間謎題 |
| 準備期 | **每關各自宣告**（§7.1 的 `PREP_TIME_TUTORIAL = 60s` 保留，但它是關卡參數不是隱藏係數——計時器就在畫面上） |

**難度層 1+ 的嚴苛係數不受影響**——那是玩家主動選擇、UI 明示的規則層（§3.11），不是偷偷改的。

### 7.9 戰役五關（★ B1.2 定案）

#### 難度階梯＝**建造欄的解鎖順序**

戰役的每一關解鎖一種新的建造選項，**那個新選項就是那一關要教的機制**。這不是把內容鎖起來拖時間（紅線 R2），而是 §7.7 那張「可用關卡參數」表的直接延伸：**第 1 關給玩家四顆按鈕，不是十顆。**十顆按鈕對一個還不知道「電是流率」的人來說不是自由，是雜訊。

| 關 | 地圖 | 新解鎖 | 要教的那件事 | 尺寸 | 橋 | 波 | 準備期 |
|---|---|---|---|---|---|---|---|
| 1 | **潮口** | 採集器・發電機・中繼・錨 | 礦砂 → 能量 → 塔，一條線走完 | 20×12 | **0** | 3 | 60s |
| 2 | **雙灣** | ＋儲槽・稜鏡 | **峰值電力**：稜鏡交戰 20/秒＝一整台發電機，而一條導管只給得起 10 | 26×15 | 1 | 4 | 60s |
| 3 | **窄橋** | ＋潮鳴・回收者 | **一座橋就是一條幹線**：北岸的礦共用它，cap 就是全關瓶頸 | 28×17 | 1 | 5 | 45s |
| 4 | **熔渣灣** | ＋熔爐 | **第三資源**：合金 → 幹線加粗到 2 級 cap 22 → 一條線扛得動整組防線 | 30×18 | 2 | 5 | 45s |
| 5 | **潮汐之喉** | ＋碎浪 | 全解鎖綜合考：礦在對岸、三座橋、五波混編 | 34×18 | 3 | 5 | 45s |

起始礦砂（也是關卡參數，§7.7）：`300 / 430 / 540 / 720 / 1240`。它隨圖變大而增加是因為**導管本身就變貴了**（3 礦砂/格，第 5 關的南緣幹線一條就 90），不是難度在放水——真正的壓力來自波次組成、準備期與橋的座數。

**★ 第 1–2 關的「新手可通關」只用關卡參數達成**（§7.7、B1.2 DoD）：波數短、只出漂蟲、礦點多且離核心近、起始礦砂寬裕、準備期 60 秒、**第 1 關零座橋**。沒有任何隱藏乘數。

**為什麼第 1 關不給稜鏡**：稜鏡交戰吃 20 能量/秒，而導管基礎 cap 是 10、升到 1 級是 16——**在拿到合金（第 4 關）之前，一條線餵不飽一座稜鏡**。第 1 關就給它，等於讓新手的第一座塔永遠掛著「缺料」徽章。錨（4/秒）在基礎 cap 底下綽綽有餘，核心循環才學得乾淨。

**第 2 關的正解是「菱形」**：發電機 →（左中繼／右中繼）→ 稜鏡，兩條 cap 10 的線並聯成 20。這是 §7.2「cap 10 < 發電機 20」那一課換到消費端再演一次，而且它給玩家的是一個**可以複製的手法**——第 3、4、5 關的稜鏡都用同一個形狀。

#### 星等（3 顆）

| 星 | 判準 | 為什麼是這個 |
|---|---|---|
| ★ | **通關**（波次表跑完且核心存活） | 撐住 |
| ★★ | **核心無損**（`core_hp` 等於滿值） | 敵人只在核心駐足——核心掉血等於「有東西走到底了」，玩家看得見因果 |
| ★★★ | **產能積分 ≥ 該關宣告門檻** | 守得住之後才問「你的生產線有多好」。用的是 §7.6 已定義的產能積分，不另發明分數 |

三顆星就是三個學習階段：撐住 → 守好 → 生產。**門檻寫在關卡資料表裡、局末結算逐條列出「拿到沒有、差多少」**，不是隱藏值。三條是**累進**的：沒通關 0 顆，核心破了封頂 1 顆——讓「產能爆表但核心快沒了」拿三星，等於把第一課教反。

**門檻是實測校準的**（B1.2，`tests/campaign_test.gd` 每次回歸重跑）：五關的參考解量到的產能積分是 `0.80 / 0.48 / 0.38 / 0.29 / 0.19`，門檻取它的 1.3–2 倍：

| 關 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| ★★★ 產能積分門檻 | 1.00 | 0.70 | 0.60 | 0.50 | 0.40 |

**門檻隨關卡遞減不是筆誤**：後面的圖更長（導管更多）、消費者更多（熔爐與第三台發電機都吃礦砂），而積分的分母含整局時間。三星的意思始終是同一句：**你的產線得比「剛好夠打」那一版好一半以上。**

#### ★ 導管不得和既有導管疊在同一排格上（B1.6.1）

使用者實看後回報「有破圖、有重疊」。根因是**兩條共線導管可以疊在同一排像素上**：畫面上是一條線、實際是兩條，兩排流動珠交錯成一團，而 `conduit_near()` 的命中判定在它們之間只能任選一條（加粗會加到你沒指的那一條）。

規則：**共用 2 格以上不准；共用 1 格照樣可以**（那是交叉或在同一個節點分岔，本來就該允許）。

這條規則刻意**不是**「不准穿過節點」——從一個節點旁邊經過而不接它，在流量網路裡是一個真的戰術選擇（接上去就得和它共用那條線的 cap）。被禁掉的只有「看起來是一條線、其實是兩條」這件事。

#### ★ 不要把塔擺在幹線的接點上（B1.6.1，關卡設計規則）

`sim/FlowNetwork` 的節點語意是**先吃滿自己的需求才轉發**。所以一座塔如果同時是幹線上的中繼，它會**餓死它下游的一切**——第 5 關的參考解一度把稜鏡當接點，結果核心旁邊那座錨滿足率 0.00，而頂欄顯示供給 60（問題從來不在發電量上）。

要讓一個大消費者拿到兩條進線，就得由**兩個中繼**（不吃電）從幹線分岔進去。第 5 關的核心因此上移一格，把 y=16 讓出來給這個菱形。

#### 兩條在 B1.2 校準時才現形的關卡設計規則

這兩條不是新設計，是既有規則的必然推論——但沒寫下來之前，五關裡有四關踩到：

1. **每一關至少要有一座塔搆得到核心。** 敵人 walk-by 永不停步，**只有核心會讓它們駐足**（§3.5）——所以任何漏到底的敵人會待在核心上啃到其中一方死。射程搆不到核心的防線，一次漏怪就是必輸，而且畫面上完全看不出為什麼。
2. **稜鏡必須和某一段路徑同排或同列。** 它的貫穿是**沿著一條軸線**（`sim/Combat.pierce_indices` 取八個方向裡命中最多的那一條），不是「射程內全打」。擺在路徑斜前方的稜鏡只打得到一兩格，看起來卻和擺對位置的一模一樣。這就是 §7.4 說的對齊謎題，它比原本寫的更強硬。

#### 獎勵

**研究數據 = `該關基礎獎勵 × 星數`**，以**歷史最高星數**結算、**只補發差額**——回頭補星拿得到，重複刷同一星數拿不到第二次。

| 關 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| 基礎獎勵 | 30 | 40 | 55 | 70 | 90 |

滿星全通＝ `(30+40+55+70+90) × 3 = 855` 研究數據，足以解掉 §7.8 十二節點裡的前六個。**戰役是科技樹的主要資金來源**——B1.3 的成本表就是照這個數量級開的。

#### 解鎖規則

第 N 關通關（≥1 星）即解鎖第 N+1 關。**沒有星數門檻**——星是給自己看的紀錄，不是閘門（紅線 R2「無等待閘門」的同一條精神：卡關只能卡在技術上，不能卡在補星上）。

### 7.10 無盡模式（★ B2.1a 定案）

#### 生成器輸出的是**和手作地圖一模一樣的一份資料**

`sim/MapGen.gd` 回傳的 dict 與 `data/Maps.gd` 的手作圖同構（`size`／`core`／`waypoints`／`crossings`／`ore`／`start_ore`／`prep_time`）。**渲染、建造、命中判定、示範佈局、截圖鉤子全部零改動**——生成器只是換一個地方生產同一種資料。這也讓「生成圖能不能玩」這件事可以直接沿用 `campaign_test` 那套斷言。

#### 佈局 1「潮汐迴廊 Tideway」

敵潮自左緣進入，正交蛇行折向右側核心。**這是五關手作圖的共同骨架**（全部是正交折線），不是新的空間語彙——B2.1a 要驗的是生成器的確定性與可通關性，不是新玩法。

| 參數 | 值 | 理由 |
|---|---|---|
| 尺寸 | **`64×40`**（★ B2.1b 由 34×18 放大） | 見下方「大過一屏」 |
| 折段數 | **`4–6`**（seeded） | 少於 4 段在 64 格寬會變成幾乎筆直的長廊、塔隨便擺都覆蓋得到；多於 6 段會擠成鋸齒，而且每多一段就多一條直走要走 |
| 縱向走法 | **單調掃掠**（★ B2.1c 改） | 見下方「掃掠與礦脈」。橫走的列由**分層抽樣**產生：`[EDGE, H-1-EDGE]` 切成 `折段數` 條等寬帶、一帶一列，**頭尾兩帶只取外側半邊** |
| 跨越點 | **`4–6`** 座 | 第 3 關教過「一座橋就是一條幹線」；路徑長到約 90 格之後 2 座橋等於整張圖只有兩個過河點 |
| 礦點 | **`20–28`** 個（★ B2.1d 改） | 總數跟著面積算（34×18 是 6–8）。**放大地圖而不動這個數字，等於悄悄把難度調高**（§7.7）。上限留了補洞的餘裕 |
| 礦點分佈 | **沿地圖面積分層**：整張圖切成 `rows×cols` 個區塊，**一塊恰好一顆**（★ B2.1d） | 「平均」是**構造出來的**，不是撒完再檢查。區塊網格取自一張表（5×4／7×3／6×4／8×3／5×5），**礦點數 ＝ 區塊數**——由 `n` 反推區塊數會多出一兩塊、多的那幾塊被跳過，畫面上就是「這一區沒有礦」 |
| 礦點離路徑 | **≥ `2` 格，Chebyshev（八方）距離** | 下限是 **walk-by 真的打不到**（§3.5）。⚠ **距離的種類要和 `Tide.in_blast()` 一致**——那支是 Chebyshev ≤ 1，用四方距離量的話**斜對角貼著路徑轉角**的礦點會通過檢查、蓋下去卻每 tick 挨打（實測 300 張圖有 167 顆）。**上限已移除**——原本的 `7` 正是「只長在路邊」的成因 |
| 平均分配的規格 | 整張圖切 **`4×3` 個大區，每一區都要有礦** | 生成器負責保證（放置後補洞），`endless_test` 獨立再驗一次 |
| 起始礦砂 | **`1900`** | 第 5 關（34×18）是 1240，而這張圖的導管長度約 1.9 倍（3 礦砂/格） |
| 準備期 | `45s` | §7.1 標準值。無盡不是教學，不給 60s |

#### ★ 十一條生成不變量（`endless_test.gd` 逐條斷言）

前四條是**格式正確**，第五條是**這張圖玩得動**，**6–9 是這張圖值不值得玩**（★ B2.1c 新增）——
那四條全部來自實玩回饋，而不是設計時想得到的：格式正確、可通關、且完全不好玩的圖，生成器一天擲得出幾千張。

1. **同種子逐格相同**——`size`／`core`／`waypoints`／`crossings`／`ore` 全欄位深度比對。
2. **路徑不自交**——展開後的路徑格無重複。自交的路徑會讓 walk-by 的傷害重複結算在同一批建築上。
3. **每座跨越點落在路徑格上**——橋不在路徑上就不是橋（§3.2）。
4. **礦點不在路徑格上、不與核心重疊**——路徑格不可蓋節點（§3.2），生成在那裡的礦點等於不存在。
5. **★ 至少 7 個礦點不必過橋就到得了核心**（B2.1a 是 3，跟著總數一起提高——`3/26` 的保證比 `3/8` 弱得多）——這一條是「生成圖必然可通關」的實質保證。橋是可規劃的安全動線，但**把所有礦砂都放在對岸**會讓開局的第一條產線非過橋不可；生成器一旦擲出這種圖，玩家的失敗原因跟他的決策無關。手作圖能靠設計者的眼睛避開，生成器只能靠斷言。
6. **★ 路徑縱向跨幅 ≥ 18 列**（B2.1c）——見下方「掃掠與礦脈」。
7. **★ 死列 ≤ 6 列**（離任何路徑列超過 6 列的列）——塔的射程與產線的合理長度都在這個尺度上，所以死列＝**畫面上有、玩法上沒有**的空間。
8. **★ 每個礦點離路徑 2–7 格**——下限是 walk-by 打不到，上限是「值不值得拉一條導管穿過空地」。
9. **★ 整張圖切 `4×3` 個大區，每一區都要有礦**（★ B2.1d 取代原本的「孤點 ≤20%」）——「平均分配」的可量版本。**前兩輪的指標都只看路徑附近**，所以「全擠在路邊」在它們眼裡是滿分。
10. **★ 沿路徑最大空檔 ≤ 40 格**（B2.1d 由 24 放寬）——礦點改成鋪滿全圖之後，「路線旁邊一定有礦」不再是承諾，這一條退居為粗略的理智檢查。原本的（連續幾格路徑旁邊沒有任何礦）——「只在某些地方有，其他地方都是空的」的可量版本。
11. **★ 半徑 4 內 ≤ 8 顆礦**——「一坨擠在一起」的可量版本。面積分層之後守的是**相鄰區塊的邊界**：兩顆各自貼著共同邊界一樣會擠在一起。

#### 無限波次

沿用 §7.6 的兩條公式，**不另發明第三條曲線**：

| 項目 | 值 | 說明 |
|---|---|---|
| 血量倍率 | `1.11^(w-1)` | 乘在敵人自己的 `hp` 上（§7.5）。`w` 自 1 起 → 第 1 波是原始強度 |
| 隻數 | `4 + floor(w/3)` | §4.2 原文 |
| 出場間隔 | **固定 `1.0s`** | 壓力曲線已經由血量與隻數表達完了。再給間隔一條曲線，玩家就分不出「這波難是因為血厚還是因為密」 |
| 敵種池 | `w≤2` 漂蟲｜`w 3–5` ＋甲殼｜`w≥6` ＋熾泳 | 與戰役同一條登場順序（§7.9）：護甲先教、能量抗性後教 |

**組成由 seeded `Rng` 從當前池中抽**，同種子同波次必得同一張出場表（§2.4 確定性）。

#### ★ 大過一屏（B2.1b）

**可讀性地板優先於「看得到全貌」。** `Shapes.MIN_READABLE_CELL = 24px` 是視覺編碼校準與驗收的基準（RG-59）；一格低於它，「一眼看出瓶頸」（R-3）就不再是驗過的事。所以無盡的縮放下限不是 fit，而是**地板**：

| | 戰役（一屏可見） | 無盡（大圖） |
|---|---|---|
| 縮放下限 | `fit`（＝地板以上） | **`max(fit, 24/32)`** ＝ 地板 |
| 「全景」鈕 | 回到 fit ＝ 全圖 | 回到**地板**，仍看不到全圖 |
| 全圖在哪裡看 | 就是主畫面 | **小地圖**（下方） |

`64×40` 的來由：框架 1152×604 在地板倍率下看得到 **48×25 格** → 64×40 看得到 **75%×62% ＝ 面積的 46%**。

**第一版做的是 56×32，實看之後改掉**：那個尺寸看得到 86%×79%，**小地圖上的視野框幾乎和外框重疊**——「我在哪」讀不出來，兩個導引通道的價值一起被稀釋。一個只是技術上大過一屏的地圖，不值得為它做導引。

**為什麼高的比寬的多加**：路徑長度 ≈ 寬度 ＋ 各段直走，而直走跨距有上限（下表）。**加高幾乎不影響一波的時間，加寬是一比一地加。**

**誠實記一個代價**：路徑變長（實測 min 90／p50 95／max 98 格，★ B2.1c 的單調掃掠把離散度從 73–119 收成 90–98——**一波的秒數不再憑種子浮動**）→ **一波的時間也跟著變長**（約 1.9 倍）。這是刻意接受的：無盡的價值在「產線能長多大」，而大圖給的正是建造空間；行走時間變長同時也讓塔的覆蓋窗口變長（偏易），由 `1.11^w` 的血量曲線自然吃掉。

#### ★ 掃掠與礦脈（B2.1c，來自實玩回饋）

使用者的原話是兩句：「**東西都集中在路線上半區，下半區很空**」「**採集器的分布顯然是隨機分布，缺乏合理規劃**」。300 個種子的實測證實兩句都成立，而且比看起來嚴重：

| | B2.1b | B2.1c |
|---|---|---|
| 路徑縱向跨幅（全高 40） | 19.3 列（最差 **8**） | **33.1** 列（最差 28） |
| 死列（離路徑 >6 列） | **26%** | **0%** |
| 礦點離路徑 >8 格 | **50%** | **0%** |
| 孤點（最近的另一顆礦 >4 格） | **72%** | 12% |
| 路徑長度（＝一波的秒數） | 95.9 | **95.1** |

**① 跨越全高的代價只付一次。** 舊版每段橫走獨立抽一列，走出來的是一條**在窄帶裡折返**的路徑：花掉 34 格的直走，只換到 19.3 列的跨幅——折返的部分是白花的。改成**單調掃掠**（由上而下或由下而上，不折返）之後，直走總長恆等於 `y[末] − y[首]`，**跨幅拿滿而路徑長度不變**。

這一點非做不可的理由是 `Tide.advance()` 是 `progress += speed * TICK`：**路徑格數就是一波的秒數**。用「把路徑拉長來填滿地圖」解這個問題，等於直接把每一波變慢——那是拿一個缺陷換另一個。

**② 礦點平均鋪滿整張圖。** 這一條改了**三次**才對，三次都是實玩回饋，而且每一次的失敗都很有代表性：

| 版本 | 作法 | 使用者的回報 | 為什麼失敗 |
|---|---|---|---|
| B2.1b | 全圖均勻**隨機**撒點 | 「顯然是隨機分布，缺乏合理規劃」 | 均勻隨機**必然結塊**——那是隨機的性質，不是 bug |
| B2.1c ① | **隨機**挑錨點再長「礦脈」 | 「一坨擠在一起，其他地方都是空的」 | 把隨機從點搬到錨點，結塊照舊 |
| B2.1c ② | 沿**路徑索引**分層 | 「只生在道路旁邊，其他區域都沒有」 | 沿路線均勻了，但 `OFF_MAX=7` 把礦鎖在路邊的帶子裡 |
| **B2.1d** | 沿**地圖面積**分層，一區塊一顆 | — | 「均勻」是構造出來的；上限移除，全圖都有礦 |

**三次共同的教訓：均勻要靠分層取樣，不能靠隨機**——而且**分層的座標系要選對**。前兩次選錯了座標系（一次是沒分層，一次是分在路徑索引上），指標也跟著只看路徑附近，於是「全擠在路邊」在指標眼裡是滿分（RG-118 的同一類錯誤）。

**③ 死區面積 45% 因此一併解掉。** B2.1c 記過「路徑是由角到角的單調階梯，對角兩個角落永遠離路徑很遠，離路徑 >10 格的格子佔 45%」。礦點鋪滿全圖之後，那些地方不再是空的——它們是**安全但要拉長線**的取捨，而那正是本作要的決策。

**④ 這一批沒有動任何難度參數。** 路徑長度、起始礦砂、跨越點數、波次公式全部不變。

#### ★ 小地圖不常駐（B2.1d.1，使用者指定）

小地圖蓋在地圖右下角。**常駐等於那一塊永遠點不到**——使用者實玩回報「有些地方會點不到」。

| | 規則 |
|---|---|
| 出現 | **縮放或平移時**（含小地圖自己的點擊與拖曳、邊緣箭頭的一鍵跳、全景鈕、進場） |
| 消失 | 視野靜止 **3 秒**後，最後 0.5 秒淡出 |
| 隱藏時 | **不攔截點擊**——這才是這條需求的重點，不是視覺上的乾淨 |

⚠ `TL_SHOT` 下**不倒數**：截圖落在第幾秒取決於這台機器跑了幾幀，會倒數的話同一組參數在不同機器上會拍出「有／沒有小地圖」兩種圖（和模擬凍結同一條理由）。

#### ★ 導引：兩個通道，缺一不可（B2.1b）

大圖模式的 R-3 驗收是「**瓶頸節點即使不在畫面內也能在 30 秒內被找到**」。兩個通道分工明確，不是互為備援：

| 通道 | 回答的問題 | 為什麼不能只留一個 |
|---|---|---|
| **小地圖** | 「**全局**現在長什麼樣？我在哪？」 | 邊緣箭頭只說「那個方向有事」，說不出「離多遠、有幾個、我的產線整體結構」 |
| **邊緣箭頭** | 「**現在**有東西壞了，在畫面外哪一邊？」 | 小地圖是常駐的靜態資訊；玩家在忙的時候不會盯著它。箭頭是**打斷式**的 |

**兩者都可點，點了就把視野移過去**（一鍵跳到問題點）。這同時是手機移植的預留（P3：操作不得只靠 hover／右鍵／鍵盤——大圖的平移目前只有中鍵，R-16；小地圖與箭頭是**純左鍵**的替代動線）。

**「問題」的定義不新發明**，就是既有的兩件事：
- **瓶頸** ＝ 節點三態徽章的 `缺料`／`滿溢`（`s.rates["node_state"]`）
- **受損** ＝ 正在被 walk-by 啃的格（`Tide.BLAST` 的同一份判定）

**一屏可見的地圖不顯示這兩個東西。** 戰役關卡全部一屏可見，問題節點就在畫面上——多一個浮層只是多一塊遮擋（§6.2「浮層收合後地圖 100% 可見」的同一條紀律）。

#### 個人最佳

記錄**撐過的波次數**與**產能積分**（§7.6 已定義，不另發明分數）。存 `SaveService`，以最高波次為主排序。**無盡是自由配置**（§3.10）——它用玩家的完整戰力，不是統一配置。

### 7.11 每日挑戰雙榜（★ B2.2 定案）

**這一批不新增任何玩法。** 每日挑戰＝**無盡模式跑在一個固定的日種子上**，跑兩次、兩種起始配置。地圖、波次、模擬、計分全部沿用 §7.10 那一套（§3.10 明文：「不得為此拆成兩套邏輯」）。

| 參數 | 值 | 理由 |
|---|---|---|
| 日種子 | **`YYYYMMDD`**（例：`20260804`） | **刻意不做雜湊混合**。① 除錯與回報時看得懂——種子會出現在截圖與錯誤回報裡；② 混合買不到東西，`Rng.stream()` 底下是 PCG32，相鄰種子本來就長出完全不同的序列（`daily_test` 直接斷言「連續 14 天的圖互不重複」）。<br>⚠ **不得改用 `String.hash()`**：那是引擎實作細節，換一版 Godot 就可能換一組數字，而「同一天全球同一張圖」是跨版本的承諾 |
| 日期鍵 | **`YYYY-MM-DD`** | 字典序＝時間序，歷史清單直接排 |
| 地圖 | `MapGen.generate(日種子)`，即 §7.10 的佈局 1 | 同一張圖跑兩榜 |
| 波次 | §7.10 的無限波次公式 | 同上 |
| 統一配置榜的起始科技 | **空陣列＝完全沒有科技** | `SessionState.setup()` 的第三個參數是**所有局外成長進入這一局的唯一入口**，堵住它就堵住全部（憲法 B3） |
| 統一配置榜的可建造 | 目前是**全部**（同無盡） | 名冊系統還沒有（B2.4）。★ **B2.4 落地時要回來把它釘死成一份明列的清單**，不要繼續用「空陣列＝全部」——那會讓日後每加一隻角色就悄悄改變統一配置榜 |
| 自由配置榜 | 玩家的完整科技 | §3.10 |
| 成績 | **波次 ＋ 產能積分，兩欄各自取最大值** | 與無盡同一條理由（§7.10）：撐得久與產線好是兩件事，綁成一組會讓一局「波次 +1、積分砍半」洗掉玩家真正的最佳產線紀錄 |
| 歷史保留 | **30 筆**（兩榜 × 15 天） | 再多也沒有人往下捲，而存檔的空間要留給玩家的進度 |

**跨日的處理在 `SaveService.apply_daily()`，不在畫面層**：畫面層有兩個入口（兩張榜）而換日只該發生一次，放在那裡就會出現「先點哪一榜決定昨天的紀錄有沒有被存進歷史」。
**跨日時今天的兩榜一起歸零**——只歸零玩的那一榜的話，昨天的另一榜會混進今天，而它是在另一張圖上打出來的。

**離線註記是規格的一部分**（§3.10）：畫面上必須寫出「兩張榜都是你自己的本機紀錄，還沒有對手」。`TL_CLICKTEST/daily` 的 `honest` 斷言守著它——不要在文案中宣稱一個尚未存在的競技場。

### 7.12 藍圖庫（★ B2.3 定案）

| 參數 | 值 | 理由 |
|---|---|---|
| 免費槽數 | **2** | 槽數 0 等於「這個功能要先買才存在」，而藍圖庫要消除的重複勞動（§3.7）**第一局就開始了** |
| 科技加成 | 後勤「藍圖槽 I／II」各 **+1**（§7.8） | 上限 4 |
| 座標格式 | **`[dx, dy]` 整數陣列**，原點是框選矩形左上角 | 藍圖要進 `user://save.json`，而 `Vector2i` 過不了 JSON（會變成讀不回來的字串）。存成 JSON 原生型別 → **存檔往返不需要任何序列化程式碼**，少一層轉換就少一個「存進去和讀出來不一樣」的機會 |
| 展開成本 | 節點造價 ＋ 導管造價的總和，**與放在哪裡無關** | 導管造價只看兩端的相對位移（Chebyshev × 每格單價），而位移是藍圖存下來的東西 |
| 展開語意 | **全有全無** | 藍圖是一個單位。半套展開＝花掉資源換到一個接不起來的殘骸，而拆掉只退 75%——那是玩家沒有辦法補救的損失。所以整份先驗過，一格不合就一格都不放 |
| 缺口提示 | **具體數字**（「礦砂差 25」）＋ **具體格子**（「有 2 格蓋不下（(21,9)…）」） | §3.7「資源不足則顯示缺口」。先講資源、再講格子：資源不足是等一下就能解決的，位置不對要他移動滑鼠——兩件事的下一步不一樣 |
| 落點預覽 | **逐格上色**（綠＝放得下、橘＝這一格擋住了） | 整份一個顏色只能說「不行」，指不出是哪一格，而那正是玩家的下一步要知道的事 |

**兩條收錄規則**（框選時）：
- **核心不收**——它蓋不出來，收進去只會讓每次展開都固定失敗一格。
- **導管要兩端都在框內才收**——只有一端在框內的，展開時另一端接不到任何節點。那不是藍圖的一部分，是它和外界的接線，而接線是玩家在新地圖上要自己決定的事。

**節點與導管排序後才存**，所以同一份佈局不論當初蓋的順序如何，框出來的藍圖逐欄相同。

**槽數吃的是玩家的科技，不是這一局的 `s.mods`**：藍圖庫是跨局資產，而每日挑戰的統一配置榜會把 `s.mods` 壓成中性值（憲法 B3）——用 `s.mods` 的話，打統一配置榜時玩家的槽會憑空少兩個。
