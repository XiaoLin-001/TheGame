## 一、立項摘要

| 欄位 | 內容 |

| **類型與參照** | 塔防 × 節點連線式自動化。參照：Mindustry（塔防＋生產）、Creeper World（連續壓力）、Factorio（生產鏈取捨）、Mini Metro（節點連線的極簡美學）。<br>**我們跟它們差在哪**：這三款的「生產」與「防禦」是**兩個獨立的資源池**——蓋好的塔只是站在那裡。我們讓**塔持續消耗生產線的產出**，於是防禦厚度與擴張速度變成同一條曲線上的兩端，取捨每一秒都在發生，而不是建造時的一次性決定。 |

## 二、設計紅線（硬性禁令，寫入文件即不可違反）

紅線的作用不是道德潔癖，是**防止後期自我背叛**：專案中後期看到留存數字不好看時，最容易的止痛藥就是簽到、體力、抽卡。紅線提前把這條路封死，強迫後期只能靠「把遊戲做得更好玩」解決問題。

| # | 紅線 | 含義 |
|---|---|---|
| **R1** | **無永久損失／刪檔** | 失敗只損失時間，不損失進度。任何模式的失敗都不得扣除已獲得的角色、解鎖、資源或關卡進度。 |
| **R2** | **無體力值／等待閘門** | 不得用時間鎖限制玩家「還能玩幾局」。玩家想玩多久就玩多久。<br>*註：tycoon 的離線生產不算體力——它是「回來收成」的正向設計，不是「不能再玩」的負向閘門。* |

### R2 在 F2P 語境下的操作定義：**賣速度，不賣次數**

專案於 2026-07-27 改為免費遊玩，R2 維持有效。它在變現設計上的具體含義：

| | 項目 |
|---|---|
| ✅ **可賣** | tycoon 加速／立即收成、升級材料（等級軸數值）、稀有角色與抽卡貨幣、外觀、通行證與禮包 |
| ❌ **不可賣** | 遊玩次數（體力）、失敗後的重試權、關卡解鎖鑰匙——**所有進度都必須能純靠遊玩取得，付費只能加快** |
| ❌ **不可做** | **付費復活**。它同時破壞 R1（失敗只花時間 → 變成失敗要花錢）與難度層／排行榜的意義 |

### 其他變現決策

- **廣告**：Windows 版**不做**（桌面無可用 SDK 生態、PC 玩家容忍度極低）。**保留至手機移植版**，屆時以獎勵式廣告為主（玩家主動觀看換取 tycoon 加速或材料）。
- **每日簽到**：不主動做。若通行證需要每日活躍設計，以「通行證任務」形式取代，且**錯過不懲罰、可補做**。理由不變：若留存要靠簽到撐，代表核心循環失敗。
- **競技公平的保障方式已改變**：不再靠「架構上不可能 P2W」（那條已隨 F2P 轉向失效），改靠**雙排行榜分層**——統一配置榜是免費玩家也能爭第一的純技術場，自由配置榜才反映總戰力。

## 三、主從結構（2026-07-27 修訂）

**遊戲主體是塔防。潮汐公司 tycoon 是它的附屬補給站，不是第二個遊戲。**

```
        ┏━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┓
        ┃         主體：塔防局                ┃
        ┃   即時、15–30 分、有壓力             ┃
        ┃   戰役 ／ 無盡 ／ 每日挑戰            ┃
        ┃                                  ┃
        ┃   產出：研究數據（科技軸）、稀有原料    ┃
        ┗━━━━━━━━━┯━━━━━━━━━━━━━━━━━━┯━━━━━┛
                  │                    ▲
  稀有原料（可選加速）│                    │ 升級材料、招募券
                  ▼                    │ 藍圖槽、難度鑰匙
        ┌─────────────────────────────┴────┐
        │   附屬：潮汐公司 tycoon             │
        │   無壓力、無失敗、可掛機              │
        │   訂單 → 產線 → 交貨 → 擴廠          │
        │   產出全部流向塔防                   │
        └──────────────▲───────────────────┘
                       │
                  【內購入口】加速／材料包
```

### 防止 tycoon 膨脹成第二個遊戲的四條約束

1. tycoon **沒有失敗狀態、沒有時間壓力、沒有對手**。它是水龍頭，不是挑戰。
2. tycoon 的 UI 深度上限：**兩個畫面**（訂單板 ＋ 產線編輯）。超過就是膨脹。
3. tycoon 的任何新機制都必須回答「**這如何讓塔防更好玩**」。答不出來就不做。
4. 市場價格波動、人事、股價、競爭對手、員工士氣 → **永久 backlog**。

### 塔防不依賴 tycoon

塔防的所有進度都**能純靠遊玩取得**。tycoon 與付費只是**加快**，不是**解鎖**。任何「不碰 tycoon 就推不下去」的設計都是缺陷。

### 競技公平：雙排行榜分層

| 榜 | 起始配置 | 誰能爭第一 | 目的 |
|---|---|---|---|
| **統一配置榜** | 固定角色組、固定科技、固定等級、固定種子 | **任何人，包含零課金玩家** | 純技術競爭；長線引擎的競技軌 |
| **自由配置榜** | 玩家自己的完整戰力 | 投入最多者（時間或金錢） | 成長曲線的展示場；變現的兌現點 |

**兩榜同種子、同地圖，只有起始配置不同**——共用一套模擬與計分，額外成本極低。這讓免費玩家永遠有一個能爭第一的舞台，同時讓付費玩家的投入有可見的展示位。

> **誠實註記（2026-07-27）**：第一版純離線，兩榜實際上是**本機的兩個最佳成績**，沒有排名、沒有對手。「對 P2W 的制衡」是**接上線上榜之後才兌現的承諾**；在那之前，雙榜架構的價值是「日後接線上榜零改動」。不要在文案或對外說明中宣稱一個尚未存在的競技場。

## 四、關卡與模式清單

| 模式 | 地圖來源 | 長度 | 目的 |
|---|---|---|---|
| **戰役** | 手作 | 15–30 分／關 | 教學、難度曲線、機制逐一introduce、解鎖主線 |
| **無盡** | 程序生成（種子） | 無上限，撐越久分越高 | 重玩性、深度精通、個人最佳紀錄 |
| **每日挑戰** | 程序生成（全球同一固定種子） | 一次性 | **雙榜**：統一配置榜（純技術）＋自由配置榜（總戰力） |
| **潮汐公司** | 非戰鬥 | 隨時可玩／離線累積 | **附屬補給站**：資源與升級材料的來源、付費入口 |

**排行榜第一版純離線**：本機保存每日種子的兩榜最佳成績，架構上分數與局面全程可序列化、可重現，日後接線上榜不需重寫。

## 五、誠實評估（立項不是啦啦隊）

### 風險 1：純即時不可暫停 × 拉線佈局 → 可能變成手速遊戲

**問題**：使用者選定的樂趣核心是「長期規劃的痛苦取捨」，明確排除手速。但同時選了「純即時不可暫停」。當敵人正在打你的節點、你還要拉三條管線時，遊戲會滑向多工操作壓力，而非規劃深度。

**對策（已納入設計）**：
1. **波間準備期**——波與波之間有安全窗口，時間與生產持續流動但無敵人，規劃在此發生。
2. **藍圖一鍵展開**——把調好的產線存成藍圖，下次一鍵放置，消除重複操作。
3. **建造預覽與吸附**——拉線時即時顯示吞吐量預測，減少試錯操作。
4. **M0 必須實測此點**：若使用者實玩後回報「忙不過來」，第一個要調的參數是準備期長度，而非難度。

**殘餘風險**：中。此為 M0 原型閘門的第二觀測項。

### 風險 2：~~局外 tycoon 是實質上的第二個遊戲~~ → **已於 2026-07-27 大幅降級**

**原問題**：tycoon 若要「可獨立遊玩」，需要自己的核心循環、經濟數值、UI 與美術，工作量近似再做半個遊戲（初估 +60~80% 時程）。

**解除方式**：使用者於 2026-07-27 將 tycoon 重新定位為**塔防的附屬補給站**（§三）。它不需要獨立的樂趣，只需要穩定產出資源。四條防膨脹約束已寫入 §三。

**殘餘風險**：**低—中**（原為高）。剩下的風險不是範圍，而是**紀律**——附屬系統很容易在生產期一點一點長大。應對：§三 的約束 2（UI 深度上限兩個畫面）是可稽核的硬指標，每批 QA 檢查。

### 風險 3：流量網路的可讀性

**問題**：節點連線式自動化的樂趣來自「看懂瓶頸在哪」。如果玩家看不懂自己的產線為什麼不夠力，最佳化的快感就不存在，整個核心取捨也失去意義。

**對策**：線的**粗細＝實際流量**、**顏色＝飽和度**（滿載變色）、節點顯示「缺料／滿溢／正常」三態。

**驗收方式（2026-07-27 修正）**：原本寫「新玩家能否在 30 秒內指出瓶頸節點」，但**沒有執行者**——樂趣與首次體驗由使用者本人判，而使用者是設計者；agent 只驗程式碼與可讀性，且它讀得到截圖上的數字，拿一般截圖問它會**必過**（假綠燈）。
改為：**`TL_NAKED=1` 隱藏所有數值標籤，只留線寬／顏色／三態徽章，把那張圖交給 Opus 5 指認瓶頸。** 這把「未受訓」翻譯成「無數值輔助」，是可執行且不會自動過的版本。答錯＝視覺編碼沒在傳達，要改的是編碼，不是問法。

**殘餘風險**：中。M0 原型閘門的第三觀測項。

### 風險 4：新手崩潰率

**問題**：「塔持續吃資源」是核心創新，但也意味著新手一旦多蓋塔就會餓死產線，形成死亡螺旋。

**對策（2026-07-27 改寫）**：原本的「新手係數」（塔待機耗能 ×0.6、敵人破壞 ×0.7）**已刪除**——待機耗能在 v0.2 已歸零，×0.6 是空操作；更根本的是，本作核心就是「學會電力數學」，在教學期偷偷改物理、第 6 關再換回來，等於前五關教了一個錯的模型。
改為：**戰役第 1–2 關以「新手可通關」為硬性設計要求，且只用玩家看得見的關卡參數達成**——敵人數量與組成、波次數、礦點密度、核心距離、跨越點座數、該關宣告的準備期。詳見 `10_GDD.md` §7.7、`40_PRODUCTION_PLAN.md` B1.2 DoD。

**殘餘風險**：中（由「低」上調）。對策從「改一個數字」變成「關卡設計工作」，成本較高但誠實。

### 風險 5：F2P × 桌面平台的結構性錯配 ★新增

**問題**：免費遊玩＋P2W 的收入模型成立於**手機**（大流量入口、成熟的內購與廣告生態、玩家習慣）。Windows 單機的分發管道（Steam）上，F2P 遊戲的獲客與變現效率遠低於手機，而廣告變現在桌面基本不存在。**首發平台與商業模式並不匹配。**

**對策**：
1. Windows 版首發 = **免費 ＋ 內購、無廣告**（Steam F2P 的標準做法）。
2. **從第一批就以手機移植為前提設計 UI 與操作**（§一「平台與交付」的四條預留條款）。事後補觸控與直式版面極痛。
3. 手機版視 Windows 版的實際表現決定是否投入；架構預留不代表承諾移植。

**殘餘風險**：**高**。這是新的頭號商業風險。**它不影響遊戲本身好不好玩**，但影響收入預期——請不要用 Windows 版的收入數字去否定遊戲設計。

### 風險 6：P2W 的數值膨脹吃掉關卡設計 ★新增

**問題**：一旦付費可買等級軸（+80% 上限），既有關卡會被輕易碾壓，難度曲線失效，遊戲變成「花錢跳過內容」。

**對策**（已寫入 `10_GDD.md` §1 B2）：
1. 等級軸與科技軸**分離**，各有獨立上限。
2. **難度層的敵人強度縮放以「等級軸滿級」為基準校準**——等級軸買到的是「能挑戰更高難度層」，不是「碾壓現有內容」。
3. **統一配置榜完全排除等級軸**，保留一個純技術的競技場。

**殘餘風險**：中。這是 M3 平衡校準的主要工作量，需用 `TL_SIM` 批次驗證。

### 風險 7：抽卡的演出與體感

**問題**：抽卡容易滑向賭博式演出，傷害遊戲調性（極簡幾何、冷靜工程感）與玩家觀感。

**對策**：抽卡池**不重複、有畢業**（抽到的必定是未擁有角色，UI 常駐顯示剩餘數）；**不使用賭博語彙**（無十連特寫、無稀有度金光、無「差一點」的假張力）。付費入口存在，但演出保持克制。

**殘餘風險**：低。
