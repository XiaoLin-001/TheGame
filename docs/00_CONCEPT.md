## 一、立項摘要

| 欄位 | 內容 |
|---|---|
| **一句話賣點** | **你的生產線就是你的防線。**在敵潮抵達之前，決定這一分鐘是擴產還是築防。 |
| **類型與參照** | 塔防 × 節點連線式自動化。參照：Mindustry（塔防＋生產）、Creeper World（連續壓力）、Factorio（生產鏈取捨）、Mini Metro（節點連線的極簡美學）。<br>**我們跟它們差在哪**：這三款的「生產」與「防禦」是**兩個獨立的資源池**——蓋好的塔只是站在那裡。我們讓**塔持續消耗生產線的產出**，於是防禦厚度與擴張速度變成同一條曲線上的兩端，取捨每一秒都在發生，而不是建造時的一次性決定。 |
| **核心循環** | 勘查地形 → 拉線佈產 → 資源流動 → **選擇：擴產 or 築防** → 波次檢驗防線 → 缺口暴露規劃錯誤 → 準備期修補再擴張 → 回到拉線。單圈 60–120 秒，一關 15–30 分。 |
| **目標玩家** | 喜歡 Factorio / Mindustry / Slay the Spire 的策略玩家；能坐下來 30 分鐘以上、享受「痛苦取捨」而非手速考驗的人。單次遊玩 20–40 分（一局戰役或一次無盡衝榜）。 |
| **樂趣假設** | **「玩家會在波次倒數剩 40 秒時，明知有風險仍選擇再擴一條產線——並且在防線破掉之後想立刻重來一次。」**<br>這句話是 G1 原型閘門的唯一驗收標準。可證偽：如果玩家永遠選擇保守築防、或破防後不想重來，假設不成立，核心機制要改。 |
| **平台與交付** | Windows exe，Godot 4.7，`gl_compatibility` 渲染。繁體中文 UI。 |
| **範圍等級** | **L（完整商業作品）**，但**先跑 M0 原型閘門**——第一個里程碑只做塔防局內、佔位美術，驗證樂趣假設後才擴大投資。 |
| **美術氣質** | 極簡幾何／向量。**視覺上的核心對立＝有機混沌（敵潮）vs 幾何秩序（你的線）**。參照：Mini Metro、Dorfromantik、Opus Magnum 的線條精度。 |
| **商業模式** | **未定**（到 Beta 前拍板）。結構上預留買斷制。抽卡系統存在但**只發放橫向內容（角色）**，不發放數值強度，且每日挑戰榜使用統一起始配置——因此**架構上不可能出現 pay-to-win**，此性質為硬性約束。 |
| **長線引擎** | 三軌並行：**(1) 成長曲線**——科技樹與 tycoon 的長期擴廠；**(2) 每日種子挑戰榜**——全球同一局面、統一配置的純技術競爭；**(3) 難度層精通**——通關後解鎖更嚴苛的規則層。 |
| **最大風險** | ① 「純即時不可暫停」＋「拉線佈局」可能讓遊戲從規劃滑向手速；② 局外 tycoon 是實質上的第二個遊戲，範圍與平衡成本翻倍。詳見 §五。 |

## 二、設計紅線（硬性禁令，寫入文件即不可違反）

紅線的作用不是道德潔癖，是**防止後期自我背叛**：專案中後期看到留存數字不好看時，最容易的止痛藥就是簽到、體力、抽卡。紅線提前把這條路封死，強迫後期只能靠「把遊戲做得更好玩」解決問題。

| # | 紅線 | 含義 |
|---|---|---|
| **R1** | **無永久損失／刪檔** | 失敗只損失時間，不損失進度。任何模式的失敗都不得扣除已獲得的角色、解鎖、資源或關卡進度。 |
| **R2** | **無體力值／等待閘門** | 不得用時間鎖限制玩家「還能玩幾局」。玩家想玩多久就玩多久。<br>*註：tycoon 的離線生產不算體力——它是「回來收成」的正向設計，不是「不能再玩」的負向閘門。* |

### 未列為紅線者（開放但不主動做）

以下三項使用者未列為紅線，**技術上允許**，但依製作人判斷不進 M0–M2 排程，僅存於 backlog：

- **每日簽到獎勵**：不主動做。理由：若長線留存需要靠簽到撐，代表核心循環失敗，做了只是把問題藏起來。
- **付費影響強度**：架構已由「橫向供給＋統一榜單」擋住，即使日後開放付費也做不出 pay-to-win。
- **廣告變現**：不在規劃內。

## 三、雙層結構與它們的關係（拍板結論）

本作有兩個可獨立遊玩的層。它們的耦合方式是本專案**最容易做錯**的部分，故在概念書層級寫死：

```
┌──────────────────────────┐        ┌──────────────────────────┐
│   第一層：塔防局（主菜）    │        │  第二層：潮汐公司 tycoon   │
│   即時、15–30 分、有壓力    │        │  經營模擬＋掛機、無壓力      │
│                          │        │                          │
│  產出：研究數據、稀有原料    │        │  產出：資金、橫向解鎖         │
└───────────┬──────────────┘        └───────────┬──────────────┘
            │                                   │
            │        ┌──────────────┐          │
            └───────►│  公司等級      │◄─────────┘
                     │（唯一共享進度條）│
                     └──────┬───────┘
                            │ 解鎖兩層的內容層級
                            ▼
    ┌───────────────────────────────────────────────┐
    │  tycoon ──【橫向供給】──► 塔防                    │
    │  ✅ 給：新角色、新建築、藍圖槽、難度鑰匙、外觀       │
    │  ❌ 不給：攻擊力／血量／射程等任何數值強化           │
    │                                               │
    │  塔防 ──【可選加速】──► tycoon                   │
    │  稀有原料可加速高階訂單，但 tycoon 也能自行採購      │
    │  （較貴）→ 任一層都能自給自足推進，不強迫切換        │
    └───────────────────────────────────────────────┘
```

**每日挑戰榜使用統一起始配置**（固定角色組、固定科技、固定種子），因此 tycoon 的產出與抽卡結果**完全不影響排名**。這一條同時解決三件事：tycoon 有明確意義、塔防不被掛機時數綁架、競技榜純比技術。

## 四、關卡與模式清單

| 模式 | 地圖來源 | 長度 | 目的 |
|---|---|---|---|
| **戰役** | 手作 | 15–30 分／關 | 教學、難度曲線、機制逐一introduce、解鎖主線 |
| **無盡** | 程序生成（種子） | 無上限，撐越久分越高 | 重玩性、深度精通、個人最佳紀錄 |
| **每日挑戰** | 程序生成（全球同一固定種子）＋統一起始配置 | 一次性 | 純技術競爭、排行榜 |
| **潮汐公司** | 非戰鬥 | 隨時可玩／離線累積 | 第二層循環、橫向資源來源、疲勞出口 |

**排行榜第一版純離線**：本機保存每日種子的最佳成績，架構上分數與局面全程可序列化、可重現，日後接線上榜不需重寫。

## 五、誠實評估（立項不是啦啦隊）

### 風險 1：純即時不可暫停 × 拉線佈局 → 可能變成手速遊戲

**問題**：使用者選定的樂趣核心是「長期規劃的痛苦取捨」，明確排除手速。但同時選了「純即時不可暫停」。當敵人正在打你的節點、你還要拉三條管線時，遊戲會滑向多工操作壓力，而非規劃深度。

**對策（已納入設計）**：
1. **波間準備期**——波與波之間有安全窗口，時間與生產持續流動但無敵人，規劃在此發生。
2. **藍圖一鍵展開**——把調好的產線存成藍圖，下次一鍵放置，消除重複操作。
3. **建造預覽與吸附**——拉線時即時顯示吞吐量預測，減少試錯操作。
4. **M0 必須實測此點**：若使用者實玩後回報「忙不過來」，第一個要調的參數是準備期長度，而非難度。

**殘餘風險**：中。此為 M0 原型閘門的第二觀測項。

### 風險 2：局外 tycoon 是實質上的第二個遊戲

**問題**：使用者要求 tycoon「可獨立遊玩」＋「經營模擬＋掛機」。這意味著它需要自己的核心循環、自己的經濟數值、自己的 UI 與美術。工作量與平衡成本近似再做半個遊戲（初估整案 +60~80% 時程）。

**對策（已納入計畫）**：
1. tycoon **排在 M2 Alpha**，M0/M1 完全不碰——先確認塔防好玩，再投資第二層。
2. 第一版 tycoon **只做一條循環**：接訂單 → 排產線 → 交貨 → 擴廠。市場、人事、股價等擴充全部進 backlog。
3. 兩層資源池**完全分離**，避免平衡互相污染（改塔防數值永遠不需要重算 tycoon）。

**殘餘風險**：高。這是整案最大的範圍風險，需在 M1 結束時重新評估是否縮減。

### 風險 3：流量網路的可讀性

**問題**：節點連線式自動化的樂趣來自「看懂瓶頸在哪」。如果玩家看不懂自己的產線為什麼不夠力，最佳化的快感就不存在，整個核心取捨也失去意義。

**對策**：線的**粗細＝實際流量**、**顏色＝飽和度**（滿載變色）、節點顯示「缺料／滿溢／正常」三態。M0 就要驗證：新玩家能否在 30 秒內指出瓶頸節點。

**殘餘風險**：中。M0 原型閘門的第三觀測項。

### 風險 4：新手崩潰率

**問題**：「塔持續吃資源」是核心創新，但也意味著新手一旦多蓋塔就會餓死產線，形成死亡螺旋。

**對策**：戰役前 5 關給予充裕餘裕（塔耗能係數降低），難度層才收緊至標準值。數值寫在 GDD §7，不在程式碼裡即興。

**殘餘風險**：低。可用數值解決。

### 風險 5：抽卡與買斷制的觀感衝突

**問題**：若最終走 Steam 買斷，內含抽卡系統會招致玩家評價抱怨，即使它不影響強度。

**對策**：抽卡貨幣**僅由遊戲內取得**，不設付費入口（除非上架前另行拍板）；抽卡產出僅限橫向內容；UI 上避免使用賭博式演出語彙（不做十連動畫、不做稀有度金光）。

**殘餘風險**：低—中。到 M3 商業模式拍板時複審。

## 六、「有沒有第二個遊戲藏在裡面？」

有，而且使用者知情並選擇保留：**潮汐公司 tycoon**。

處置：**不砍，但延後到 M2，且第一版限縮為單一循環**。若 M1 結束時塔防層的打磨仍未收斂，製作人有權將 tycoon 降級為「橫向資源的簡化介面」並將完整版移入 backlog——此決定權需經使用者同意。
