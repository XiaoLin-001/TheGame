# 《潮與線》美術方向

> **視覺／動效／音訊的唯一權威。** UI 一律引用本文件的 token，不得硬編碼新色值或新間距。
> 上位文件：`00_CONCEPT.md`、`10_GDD.md`。
> 狀態：**v0.2**（新增 §1.6 地圖元素視覺語言含跨越點；HUD 改浮層；一致性檢查加 `TL_NAKED` 檢定）　|　最後更新：2026-07-27

---

## 0. 核心視覺命題

> **有機混沌（敵潮） vs 幾何秩序（你的線）。**

這不是裝飾性的風格選擇，而是**把遊戲主題直接畫出來**：玩家建造的一切都是**直線、正圓、銳角、對齊網格**；敵潮則是**曲線、不規則、脈動、不對齊**。玩家看著自己的秩序被混沌侵蝕，再把它重建回來——這正是核心循環的情緒。

這條命題支配以下所有決策。任何新增視覺元素都必須回答：**它屬於秩序還是混沌？**

| | 秩序（玩家） | 混沌（敵潮） |
|---|---|---|
| 形狀 | 正圓、正方、等邊多邊形 | 不規則凸包、水滴、鋸齒 |
| 線條 | 直線、90°/45° 轉折 | 貝茲曲線、抖動 |
| 對齊 | 嚴格對齊 32px 網格 | 完全不對齊 |
| 動態 | 恆定速率、線性或 ease-out | 呼吸式脈動、隨機微抖 |
| 色相 | 青／琥珀（冷靜、機械） | 品紅／紫（有機、危險） |

| **`tide.magenta`** | `#ff4d6d` | **敵潮主色**：敵人本體 |
| `tide.deep` | `#7b2d5e` | 敵潮陰影、來襲方向指示 |

| `ok.green` | `#5fd39a` | 成功：交貨完成、解鎖、關卡通過 |
| `text.primary` | `#e8f1f5` | 主要文字 |
| `text.secondary` | `#8ba3b0` | 次要文字、單位、說明 |
| `text.disabled` | `#4a5f6b` | 停用文字 |

**配色紀律**：
- 全遊戲**只有敵人與危險狀態能用品紅／橙**。這保證玩家的眼睛永遠能在混亂的畫面裡瞬間找到威脅。
- 琥珀色**專屬於能量**。看到琥珀＝跟耗能有關。這是本作最重要的資訊通道（能量＝取捨的化身）。

### 1.3 間距階

`4 / 8 / 12 / 16 / 24 / 32 / 48`（px）。**不得使用階外數值。**

### 1.3b 手機移植預留條款（從第一批就生效）

Windows 先行，但事後補觸控支援極痛，故以下四條在每批 UI 一致性檢查中稽核：

| # | 條款 |
|---|---|
| P1 | **版面全部可縮放**。以 16:9 為基準，但**不得硬編碼像素位置**——一律用錨點、容器與比例。 |
| P2 | **所有可點元素的觸控命中區 ≥ 44×44 px**（視覺可以更小，命中區不行）。 |
| P3 | **操作不得只靠 hover／右鍵／鍵盤快捷**。這些可以有，但每個功能都必須有一條純點擊／拖曳的途徑。 |
| P4 | **關鍵資訊不得只靠 tooltip 呈現**（觸控裝置沒有 hover 態）。 |

**P2 的直接後果（2026-07-27）**：局內 HUD 從三欄式改為**全畫面地圖 ＋ 浮層／抽屜**（`10_GDD.md` §6.2）。固定窄欄塞不下 9 個 44×44 px 的建造項目，硬塞就會犧牲 P2 或犧牲地圖面積。浮層還必須**可收合**，收合後地圖 100% 可見。

### 1.4 圓角與線寬

| Token | 值 | 用途 |
|---|---|---|
| `radius.none` | 0 | **遊戲內所有玩家建築**（秩序＝銳角） |
| `radius.ui` | 2 | UI 面板與按鈕（僅此一種） |
| `stroke.hair` | 1 | 分隔線、網格 |
| `stroke.base` | 2 | 節點外框、UI 邊框 |
| `stroke.emphasis` | 3 | 選中、聚焦 |

**導管線寬為動態值**：`width = 2 + 6 × (flow / cap)`，範圍 2–8px。這是遊戲最重要的資訊視覺化——**線的粗細就是流量**。

### 1.5 網格

地圖網格 **32px**。所有玩家建築嚴格對齊。網格線用 `border.subtle` 於 1px，透明度 20%。

### 1.6 地圖元素的視覺語言（★ 新增）

| 元素 | 畫法 | 為什麼 |
|---|---|---|
| **敵人路徑** | `tide.deep` 的低透明度帶狀底色 ＋ 不對齊網格的抖動邊緣 | 它屬於**混沌**側。玩家一眼看出「這條帶子不是我的」 |
| **跨越點（橋）** | 路徑帶之上的一段**架高結構**：`order.cyan` 的雙線橋面 ＋ 兩端 45° 引道 ＋ 橋下留可見的路徑帶陰影 | ①「架高」必須用畫的說清楚——它是**橋上導管不受攻擊**這條規則的唯一解釋（`10_GDD.md` §3.2）。玩家看到它跨在上面，就不會問「為什麼這段打不到」。②它屬於**秩序**側，是玩家可用的動線 |
| **礦點** | `order.dim` 的空心正圓，蓋上採集器後填實 | 秩序側，可用資源 |
| **核心** | 最大的幾何體，`order.bright` 描邊；受擊時整體閃 `warn.orange` | 唯一會讓敵人駐足的目標，必須最顯眼 |

**硬性要求**：**跨越點必須在不縮放、不 hover 的狀態下一眼可辨**（`10_GDD.md` §3.2）。玩家不該靠試錯才知道哪裡能鋪管——那是浪費 45 秒準備期的操作成本（R-1）。

## 2. 氣質與參照

**一句話氣質**：*冷靜的工程製圖，正在被某種活的東西侵蝕。*

**參照座標**：

| 作品 | 我們取什麼 |
|---|---|
| **Mini Metro** | 線條的絕對克制；用最少的形狀傳達最多的拓樸資訊 |
| **Opus Magnum** | 機械運轉的節奏美感；每個零件都看得懂在做什麼 |
| **Dorfromantik** | 柔和但精確的色彩層次；不刺眼的長時間可讀性 |
| **Creeper World** | 有機威脅緩慢吞噬幾何秩序的視覺張力 |

### 反模式清單（明確「不是」我們的風格）

- ❌ **賽博龐克霓虹**：不用高飽和紫粉漸層、不用故障（glitch）特效、不用掃描線。
- ❌ **寫實科幻**：不用金屬材質貼圖、不用鏡頭光暈、不用體積光。
- ❌ **可愛化**：角色不擬人、不加表情、不做 Q 版。塔是機械，不是吉祥物。
- ❌ **資訊過載的 HUD**：不做同時顯示 20 個數字的儀表板。每個畫面最多 4 個「主要數字」。
- ❌ **賭博演出語彙**：招募畫面不做金光、不做十連特寫、不做「差一點」的假張力（`10_GDD.md` §3.9）。
- ❌ **粒子濫用**：爆炸不用 200 顆粒子。用 3–5 個幾何碎片＋一次縮放閃光。

## 3. 字型

| 用途 | 字型 | 說明 |
|---|---|---|
| 全部 UI 與遊戲內文字 | **`SystemFont`**（微軟正黑體 / Microsoft JhengHei，fallback：Noto Sans TC） | **硬性要求**：Godot 預設字型不含 CJK，直接使用會變豆腐字。 |
| 數值顯示 | 同上，但**啟用等寬數字**（tabular figures） | 資源數字跳動時不得左右位移。若引擎不支援，改用固定寬度容器 + 右對齊。 |

**禁止**：不得改回 Godot 預設字型；不得為了風格引入不含中文的英文字型作為主字型。

## 4. 動效原則

### 4.1 時長階

| Token | 時長 | 用途 |
|---|---|---|
| `dur.instant` | 0.12s | 按鈕回饋、hover、選中框 |
| `dur.base` | 0.24s | 面板開闔、數值補間、狀態切換 |
| `dur.slow` | 0.50s | 畫面轉場、局末結算逐項揭示 |
| `dur.ambient` | 2.0s+ | 敵潮脈動、背景呼吸（循環） |

### 4.2 緩動

- **玩家操作的回饋**：`ease-out-cubic`（快起慢收＝有回應感）
- **系統自動的變化**（資源數字、流量粗細）：`linear`（＝機械的誠實，不誇張）
- **敵潮的動態**：`ease-in-out-sine` 循環（＝有機的呼吸）

### 4.3 什麼動、什麼不動

| 一定要動 | 一定不動 |
|---|---|
| 導管粗細（隨流量即時變化） | 網格 |
| 能量條（含警示脈動） | 已放置節點的位置 |
| 敵人本體（脈動＋前進） | UI 面板容器 |
| 波次倒數最後 10 秒（數字脈動） | 文字（不做打字機效果） |
| 建造預覽（半透明幽靈） | 背景（不做視差） |

### 4.4 可跳過原則

**所有動效都可跳過。** 設定裡提供「減少動態效果」開關（一併關閉脈動、閃光、轉場），這既是無障礙需求，也是高手快速重來的需求。局末結算的逐項揭示可按任意鍵直接跳到底。

## 5. 音訊方向

**氣質**：低頻環境嗡鳴 ＋ 機械節奏 ＋ 有機威脅音。像在一座深海工廠裡工作，而外面有東西在敲玻璃。

### 5.1 音軌

| 類別 | 內容 | 里程碑 |
|---|---|---|
| BGM 準備期 | 低頻 drone ＋ 稀疏的機械節拍，平靜 | M1 |
| BGM 戰鬥期 | 同一主題疊加打擊層與失諧的高頻，**無縫接軌**（同 BPM、同調性，只切層） | M1 |
| BGM 主選單 | 極簡、留白多 | M1 |
| BGM tycoon | 溫暖、低壓力、可長時間聆聽 | M2 |
| SFX 建造 | 節點放置（短促金屬扣合）、導管連接（上升掃頻） | M0 |
| SFX 生產 | 資源流動的低頻循環（音量隨總流量微調） | M1 |
| SFX 戰鬥 | 各角色開火音（4 種，可辨識）、敵人受擊、建築損毀 | M0 |
| SFX 警示 | 能量不足（低頻警報）、核心受擊（最醒目的一個音） | M0 |
| SFX UI | 點擊、確認、取消、解鎖 | M1 |

**BGM 分層設計**：準備期與戰鬥期用同一首曲子的不同層，切換時**只淡入淡出音軌層**，不換曲。理由：頻繁換曲會讓 15–30 分鐘的一局變得吵雜疲勞。

### 5.2 音量層級

| 匯流排 | 預設 |
|---|---|
| Master | 80% |
| BGM | 60% |
| SFX | 80% |
| UI | 70% |

### 5.3 全域靜音路徑（硬性要求）

- 設定面板提供 Master／BGM／SFX 獨立滑桿。
- **環境變數 `TL_MUTE=1` 或任何 `TL_SHOT` 存在時，自動全域靜音。**
- **絕不在沒有測試鉤子的情況下開啟遊戲視窗做自動化驗證**——使用者可能正在工作或遊玩。

## 6. 素材生產管線

### 6.1 全程序繪製，零外部圖檔

**決策**：所有遊戲內視覺元素以 Godot 的 `_draw()` API 與自訂 shader **程序繪製**，不使用任何外部 PNG／SVG 素材。

**理由**：
1. 極簡幾何風格的元素本來就是圓、線、多邊形——用繪圖 API 表達比用貼圖更自然。
2. 任意解析度下都銳利（向量本質），不需要多套解析度資產。
3. 導管粗細隨流量即時變化，本來就必須是程序繪製。
4. exe 體積可控（目標 < 80MB），且無授權疑慮。
5. 調色只需改一處 token，全遊戲同步。

**例外**：字型（SystemFont，系統提供）、音訊檔案。

### 6.2 命名與目錄慣例

```
godot/
  assets/
    audio/
      bgm/       tl_bgm_<場景>_<層>.ogg      例：tl_bgm_battle_perc.ogg
      sfx/       tl_sfx_<類別>_<動作>.wav    例：tl_sfx_build_place.wav
  scripts/
    render/      Palette.gd    ← 本文件 §1 的 token 實作，唯一色值來源
                 Shapes.gd     ← 共用繪圖函式（節點、導管、敵潮輪廓）
                 Motion.gd     ← 本文件 §4 的時長與緩動常數
```

**硬性要求**：`Palette.gd` 是全專案唯一的色值來源。任何 `Color(...)` 字面量出現在其他檔案，視為缺陷。

### 6.3 UI 一致性檢查（每批工作結束時）

- [ ] 沒有新的硬編碼色值（Grep `Color(` 只應命中 `Palette.gd`）
- [ ] 沒有階外間距（4/8/12/16/24/32/48 以外的 margin/padding）
- [ ] 沒有階外字級
- [ ] 新增的玩家側元素是銳角、對齊網格；新增的敵潮側元素是曲線、不對齊
- [ ] 新增動效使用 `Motion.gd` 的時長階，且可被「減少動態效果」關閉
- [ ] **手機預留條款 P1–P4 全過**（無硬編碼像素位置、觸控命中區 ≥ 44px、無 hover-only 操作、無 tooltip-only 資訊）
- [ ] **浮層可收合，收合後地圖 100% 可見**（`10_GDD.md` §6.2 要求 5）
- [ ] **★ `TL_NAKED=1` 檢定**：關掉所有數值標籤後，這一批新增的視覺元素**自己還說得出話嗎**？（線寬＝流量、顏色＝飽和度、三態徽章、跨越點可辨）——**這是本文件所有資訊視覺化的最終驗收方式**，見 `50_QA_PLAN.md` §0.1
